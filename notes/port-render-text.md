# Порт рендера — шрифты и текст (шаг 3). Полный кадр сошёлся

## Что портировано (js/render/text.js, claims/0x29bbd 0x29c38 0x29c82 0x28a94 0x2572f 0x25f94)
- **0x29bbd выбор шрифта.** Таблица `0x46f14`, шаг `0x1c`: флаги, ширина, высота, база, байт/глиф, байт/строку, смещение данных → копируются в `0x47024..0x4703c`, `[0x47020]`=id. CF=1, если id≥8 или у шрифта не выставлен бит 1 флагов. Загруженные шрифты: 0 = 8×8 (флаги 7), 1 = 8×16 (7), 2 = 16×16 (5).
- **0x29e71 глиф 8 бит/пиксель** — реальный путь для всех загруженных шрифтов (условие `[0x47024]&4`). Байт глифа 0 — прозрачно (или `[0x4700d]`, если не 0), иначе цвет = `байт + [0x4700c] − 1`, т.е. шрифт хранит градации, а `0x4700c` — база палитры. Ширина: при флагах==6 фиксированная `[0x47028]`, иначе из таблицы ширин (первые 256 байт шрифта по `[0x47030]`), обрезанная до `[0x47028]` для отрисовки, но перо двигается на НЕобрезанную (`[0x47048]`) + `[0x47018]`. Отсечение построчно по `0x46ff4/0x46ff8/0x46ffc/0x47000` и по 640/480.
- **0x29d40 глиф 1 бит/пиксель** — портирован буквально, но ни один загруженный шрифт этим путём не идёт (в трассах не исполняется).
- **0x29c93 символ** (тень: при `[0x4700f]&1` сначала цветом `[0x4700e]` со сдвигом `[0x47010]/[0x47014]`, потом сам символ с `[0x4700d]=0`; `push word [0x4700c]` — это пара цвет+фон), **0x29c38 строка** (байт с битом 0x80 — первый из пары, 0x29f68), **0x29c26** (x,y из `[esi]`/`[esi+4]`), **0x29c82** (строка без двухбайтовых).
- **0x28a94 / 0x28ab9 / 0x28add** число → десятичная строка задом наперёд от `0x446e8`, делитель `[0x446ea]`/`[0x446ee]`, возврат edx.
- **0x2572f тексты поверх карты**: чат (8 строк, y 304 шагом 16, счётчики показа `[0x333c1+i]`), «Message>» + 0x2a913 при `[0x333c9]`, **«FOODS=» в (260,0)** при `[0x31c48+p*4]`, сообщение в (120,380) цветом 0xc4 с таймером `[0x41922]`, еда выделенного своего юнита в (0,464). Все таймеры тикают по BIOS-таймеру `[0x46c]`. ВАЖНО: если `[0x41920]` совпал с таймером, оригинал уходит в ret (`je 0x2593d`) — нижняя часть функции в этом кадре не рисуется.
- **0x25f94 надпись над юнитом** (эффект №58 пула `0xf2504`): строка из таблицы `[0x42410 + [+8]]`, цвет `[+3]`, позиция = координаты юнита `[+4]` минус подъём `[+0xc]` минус камера. Диспетчер `0x25cbc` в scene.js: заглушка `proj58_text_0x25f94` заменена вызовом.

## Ключевая находка: указатели шрифтов сдвинуты
Базы шрифтов в снимке эталона лежат со сдвигом **+0x100000** (та же история, что с указателями слотов спрайтов). Без поправки `[0x47030]` = 0x724ab8 указывает за пределы сегмента и текст молча не рисуется. Добавлена `fixFontPointers(m)` (text.js), вызывается в конструкторе `Renderer` рядом с `fixSlotPointers`.

## Проверка
- **Полный кадр 640×480 без исключений: 0 расхождений на всех трёх render-трассах** — m0_t0 (11 кадров), m2_t0 (13), m9_t3 (17). До этого шага расходились «FOODS=» (x 260..346 y 1..12) и надписи над юнитами/сообщение на m9.
- Симуляция не тронута: `compare.mjs` — m0_t0 200/200, m0_t0_orders 300/300, m1_t1 300/300, m2_t0 300/300, m5_t0 300/300, m9_t3 400/400, m3_t5 300/300, непортированных вызовов нет.

## Осталось
- `0x29f68` (двухбайтовые/корейские символы, шрифт 2) — в трассах не встречается, не портирован; `0x2a913` (строка ввода чата) — вызывается только при `[0x333c9]`.
- Браузерный просмотрщик (`web/`) до сих пор рисует своим отладочным способом: `web/gen_modules.py` собирает только `js/port`, без `js/render`. Подключить настоящий рендер — следующий шаг.
- Перегенерация всех трасс исправленным эталоном (счётчик шагов dword) и итоговая сверка.

## Просмотрщик переведён на настоящий рендер (2026-09-07)
`web/viewer.js` больше не рисует тайлы и спрайты сам — он гоняет порт рендера оригинала: `Renderer.drawFull()` на первом кадре,
`drawTick()` дальше, `fb.toRGBA()` → `putImageData` в канву 640×480. Палитра в памяти (`0x44980`) уже 8-битная, масштабировать не нужно.
`web/gen_modules.py` теперь кладёт в `js/modules.browser.js` не только `js/port/*.js`, но и модули рендера, регистрирующие функции в `F`
(`scene, sprites, hud, panel, text` — в том же порядке, что `js/modules.js`; `renderer.js`/`fb.js` просмотрщик импортирует сам, это классы).

**Проверка:** кадр 0, снятый из настоящего браузера (`window.__jw.fb.px` со страницы <your host>), сравнён с эталонным кадром
`traces/render_m0_t0/frame_0000.bin.z` — **0 расхождений из 307200 пикселей**. То есть браузерный путь (boot_snap + `loadMission`)
даёт ровно ту же картинку, что путь Node (снимок трассы), и оба совпадают с DOS-оригиналом.
