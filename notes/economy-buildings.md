## 1. Еда
- **Еда игрока** `g_food[8]` = u32 @0x31c28 (индекс owner). Это еда, ЛЕЖАЩАЯ В СКЛАДАХ. Число складов игрока `g_nStorage[8]` = u32 @0x31c48.
  Читы/бонусы: +1000 (FUN_10d44), +5000/+20000 (FUN_1545a: 0x1553e/0x155cc — миссионные события), +50000 (FUN_27844 case 6 — чит-код меню).
  Старт: FUN_22ffc @0x232b7 ставит еду обоим игрокам из значения FUN_28b44 (из GI сценария, +0x14 = 50 у всех карт).
- **Еда у юнита** — поле `U_COST` (+0x13, u16) = *несёт еды*. Инициализируется из T_STATS[type][6..7]: люди 30, приручаемые дино 30, дикие звери = МЯСО (T-Rex 1000, Brachio 950, Centro 900, Stauri 800, Daemon 750, Mammoth 700, Musso 400, Tiger 350, Leopard 200, Cur 150). Слоты инвентаря +0x1b..+0x26 (12 байт, id предмета; 0=пусто); слоты 6..8 (+0x21..+0x23) зарезервированы под еду (id 0x1e), при создании +0x21 = 0x1e.
  FUN_1c679: добавить еду (насыщение 0xffff, помечает слот 0x1e). FUN_1c6e9: списать еду (при 0 слот очищается).
- **Как добывается**: убитый юнит/зверь (0x1975c, состояние 0x6f→0x60) выкладывает на землю ВСЕ 12 слотов, еда — предметом 0x1e с количеством U_COST (FUN_1ca54 выделяет запись предмета, структура предмета @0xf4f34: +0 id, +1 x(тайл), +2 y, +4 таймер(=0x19), +6 количество, +8 prev, +0xc next; список 0x31b7c; в сетке G_BI_GRID ставится бит 2 = «на тайле лежит предмет»). Т.е. охота = убить зверя и подобрать мясо. Растения (Apple/Herb/Ginseng) — предметы-еда для «eat».
  Подбор: состояние Take 0x4x (0x1918c): бит 4→2 = дойти, бит 1 → FUN_1c409 (перебор предметов на своём тайле, FUN_1c470 кладёт в инвентарь). Лимит переноски: если U_COST ≥ HP_MAX·64 (0x191d8) — юнит перегружен и идёт к ближайшему складу (0x17361 → FUN_23da0 ищет ближайший свой Food-storage по манхэттену).
- **Склад (тип 30 Food-storage)**: сдача еды — состояние 0x5x (Give/Store/Sell/Drop, «использовать слот n», 0xe4451 = n): цель типа 0x1e → за один тик переносит min(50, U_COST) в g_food[owner] (0x194af: `cmp ecx,0x32; sub ecx,0x32` — порциями по 50, как в мануале). Цель Armory (0x1c/0x1d) → продажа предмета: цена = 5·factor[id] (0x30fac=5, 0x315ec[id]) >> 1 (половина) — еда зачисляется НЕСУЩЕМУ юниту (FUN_1c679). Цель-юнит (<0x1a) → передать предмет (для еды — половину: `shr ax,1`). Без цели → бросить на землю (еды — половину).
  Выдача со склада: меню склада, обработчик 0x1d691: выкладывает на землю у склада (x, y+64) предмет-еду на сумму min(g_food, T_withdraw[idx]) где T_withdraw @0x37564 = [10, 100, 1000, 10000]; время «производства» — 315ac[30][idx] = 5,10,15,20 шагов, цена 0.
  Гибель склада (0x1886e): доля = g_food/(nStorage+1); g_food −= доля; nStorage−−; доля выкладывается на землю кучками по убыванию вдвое (пока ≥50). Захват склада конструктором (0x1d9cd): доля = food/nStorage переходит новому владельцу (вместе со счётчиком).
  HUD (FUN_2572f): иконка/число общей еды рисуется, только если g_nStorage[player] != 0; «Foods=» показывает еду выбранного юнита.
- Победа миссии 1 «Acquire Food over 3,000» — FUN_17989: сумма U_COST по ВСЕМ живым юнитам игрока (включая здания!) ≥ 3000 → DAT_30349 = 2.

- **Механика оплаты (0x189bb–0x18ab1, 0x18723–0x18847)**: заказ = состояние 0x7f: 0xe4409 = число шагов (315ac), 0xe441f = еда за шаг (30eac), 0xe441b = уплачено, 0xe440a = сделано шагов; FLAGS50 |= 1. Каждый «медленный тик» (когда счётчик 0x31b66 == 0, т.е. раз в 16 кадров): если g_food ≥ еда/шаг → списать, шаг++; когда шагов > нужного — спавн. Если еды нет → FLAGS50 |= 4 (пауза, сообщение FUN_26d8c), повторный 0x7f снимает паузу. Состояние 0x7e = отмена: возврат уплаченного в g_food. Т.е. цена платится постепенно, а «steps» — это и время производства.
- **Постройка**: Sanctuary тренирует Constructor (тип 4, HP 20/ATK 10/DEF 10/SPD 10 — самый слабый человек) с записанным видом здания K. Игрок ведёт его на место и жмёт иконку постройки: заказ 0xe0 (caseD_e0 @0x1d1cf): по прибытии в целевую клетку **сам конструктор превращается в здание**: тип = K+26, состояние 0, FLAGS50 = 2 (стройка), HP=0, инвентарь выкладывается на землю; если K=Storage → nStorage++. Стройка: каждый медленный тик HP++ (0x1880c) до HP_MAX → готово (время = HP_MAX·16 кадров; Sanctuary 255 тиков). Проверки места: FUN_1ce81 (проходимость по TRT/INF и BI-сетке) → «Can't build here».
- **Ремонт**: любое здание с HP<HP_MAX в состоянии 0 получает +1 HP за медленный тик (0x18847) — «buildings repair themselves as time goes on».
- **Захват** (0x18cc6/0x1d9cd): Constructor с 0xe4459 = 0x0e (спец. «capture») + цель чужое здание → владелец здания меняется; текущий заказ отменяется (кроме Armory), доля еды склада переезжает. Сообщение «Capture a structure.»
- **Разрушение** (0x1886e): при HP→0 состояние 0x6f→0x60, спрайт взрыва (0x975/0x97a = 2421/2426 + кадр), склад — см. выше; если здание кого-то тренировало, заказчику (0xe4423) ставится таймер 0x64.

## 3. Тренировка/популяция
- Очереди нет: одно здание — один заказ (0xe4433 = индекс меню). Повторный клик при паузе снимает паузу, 0x7e отменяет с возвратом.
- Лимита населения не найдено. Счётчики g_cntByOwner @0x36bf0 / g_cntByType @0x36c04 пересчитываются FUN_178e7/FUN_1794e и читаются в FUN_17b47.. только для проверки «у игрока не осталось юнитов» (условия поражения) и «остались ли здания».
- ИИ (owner с DAT_32aec[owner]≠0): у каждого юнита ИИ тикает T_TYPE_TIMER[type] (@0x36d84: люди 360–720, дино 1080, звери 5400–8100…); по истечении (0x1ced8) ищет своё здание-производитель (0x1cfa3[type]) и, если g_food ≥ полная цена (шаги×еда/шаг), ставит заказ на такой же тип; иначе, если (0x32b0c−0x32b2c)[slot] < 5 — вызывает FUN_15f1c (мобилизация). Дикие звери (0x1cfcb): респавн в прямоугольнике 0xe4455..0xe4458 через T_TYPE_TIMER+счётчик 0x33358[type]. Растения (0x1d12e): отрастают на месте.

## 4. Приручение динозавров
Отдельной механики приручения НЕТ: «ручные» динозавры (9–13) просто тренируются в домах 35–39 за еду (Velociraptor 1400+, Triceratops 2100+). Дикие 14–23 — только добыча мяса. Племя влияет на набор доступных зданий/спрайты (не разобрано: где хранится доступность по племени; строка «Tribe of TYRANO…» @0x41a8c).

## 5. Структура записи юнита (дополнение)
+0x05 слот игрока (player idx), +0x07 флаги выделения (0x80 выбран), +0x08 AI-группа, +0x09 шагов заказа, +0x0a шагов сделано, +0x13 еда u16, +0x15/+0x16 экипированные слоты (оружие/щит; 0xff нет), +0x17 u32 опыт?, +0x1b..+0x26 инвентарь 12 слотов, +0x1f u32 еда/шаг заказа (перекрывает слоты 4..7! — у зданий), +0x1b u32 уплачено (у зданий), +0x23 указатель-заказчик (у зданий), +0x2b состояние, +0x2c субсчётчик, +0x2d спрайт u16, +0x33 цель/индекс меню, +0x37/+0x39 цель x,y, +0x44/+0x45 тайл x,y, +0x46 отложенный приказ (0xff нет), +0x47 цель приказа, +0x4b/+0x4d x,y приказа, +0x4f таймер типа, +0x50 флаги здания (1 тренирует, 2 строится, 4 пауза-нет-еды), +0x51 слот-аргумент/прогресс стройки, +0x53/+0x54 «дом» x,y, +0x55..+0x58 зона респавна, +0x59 вид здания у конструктора / x респавна, +0x5b флаги (1 мёртв, 2 …).

## Неясное
- Таблица «здание+племя → спрайт» (номера 2442–2525) не найдена; вероятно через PTR_DAT_00030dd8/DAT_00030dcc.
- Asymmetry: покупка в Armory индексирует factor по idx меню (0..14), продажа — по id предмета (1..14) → продажная цена Sword считается по factor[1]=66, а покупная по factor[0]=70; либо меню Armory начинается с id 0 «None». Требует проверки в игре.
- Значение поля SPD у зданий (200/150/180/255) и T_STATS_ATK=0/DEF=255 — как используется при атаке зданий.
- Значения T_TYPE_TIMER для зданий (26–39: 540,540,1080,1080,540,1080…) — ИИ-тик здания, что именно делает 0x1ced8 для зданий (1cfa3[26..39]=26 → «Sanctuary тренирует конструктора для здания того же типа» — похоже на авто-восстановление разрушенных зданий у ИИ).
- 0xe4405 (player slot) vs 0xe4406 (owner): чем различаются (сетевая игра HOST/SUB?).
- Точная частота «медленного тика» (0x31b66 &0xf) в секундах — нужен главный цикл.
