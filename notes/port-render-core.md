# Порт рендера — ядро сцены (js/render/scene.js, js/render/sprites.js)

## Как устроен вывод в оригинале
- Кадр рисуется в **закадровый буфер `0x1235f4`** (640×480, 640 байт/строка; таблица смещений строк `0x122e74`, dword на строку). `[0x46f00]` = `[0x47640]` = `[0x488c0]` = 0x1235f4. Flip `0x299b4`: копирует палитру `0x466fc→0x462fc`, прячет/показывает программный курсор (`0x29771/0x297b5` — курсор рисуется **в VRAM**, не в буфер), `0x2ade6` копирует 0x4b000 байт буфера в VRAM банками по 64К (`[0x47634]`, банк через `0x2acb5`). Значит кадр эталона = `mem[0x1235f4..+0x4b000]` + курсор.
- Вьюпорт карты: `[0x488c4]`=512, `[0x488c8]`=480 (режим `[0x31ae0]&1`: 16×15 тайлов, `[0x31af0]/[0x31af4]`); камера `[0x31ae8]/[0x31aec]` в пикселях, кратна 32. Панель справа с x=512.
- **Спрайты**: таблица слотов `0x16e5f4`, 16 байт: u32 ptr на пиксели (в памяти данных!), u16 w, u16 h, i16 hx, i16 hy (смещение для обычного вывода), i16 hx2, i16 hy2 (для зеркального). Пиксели грузятся при старте в область от `[0x48874]`=0x179cd4 (пак 04 слоты 0..2838 через `0x2bd56`), тайлсетные/племенные спрайты пака 05 — 19 штук со слота 0xb17 (`0x10b29`→`0x2bcc0`, освобождение `0x2bbbd`). Число слотов `[0x48870]`, максимум 0xb6e. В снимках эталона указатели слотов сдвинуты на +0x100000 (runtime, не fixup) — `fixSlotPointers()` снимает сдвиг.
- **Блиттеры** (eax=слот, edx=x, ebx=y, возвращают CL=1 если целиком вне вьюпорта): `0x2c1df` копия + тень (пиксель 1 → LUT `0x44f80[dest]`); `0x2c320` силуэт цветом `[0x488e9]` (1 остаётся 1); `0x2c460` командные цвета (0xc0..0xc3 += `[0x488e8]`) + тень; `0x2c5b5` копия с отсечением по 640×480; `0x2c6e7/0x2c82f/0x2c970` — зеркальные версии (hotspot hx2/hy2, вывод справа налево); `0x1f815` без отсечения; `0x1f875` «стекло» через LUT `0x38210[(p-0xb)*256+dest]`. Отсечение хранит промежуточные значения в `0x488cc..0x488e4`.
- Выбор блиттера юнита: индекс `((+0x43&1)<<1) | (dir<6)` в таблице `0x3eb00` = [0x2c970, 0x2c460, 0x2c82f, 0x2c320] (направления 6,7 зеркалятся; паралич = силуэт).
- Результат блита пишется в поле юнита **+0x42 бит 0** (1 = не на экране). `0x24d70` сначала ставит 1 всем, обработчики снимают у нарисованных. Симуляция читает его как «юнит на экране» (звуки) — поэтому при сверке кадров JS рендерит после каждого тика, как оригинал.

## Последовательность (0x23eb1 полная сцена / блок в 0x17e1c каждый BIOS-тик)
`0x242d4` тайлы (индекс `BG&0x7ff`, 32×32 из `0x49b2c`) → `0x26498` объекты на земле (список `0x31b7c`, +0 тип → спрайт 0x9de+тип; еда 0x9fc/0x9fd/0x9fe по количеству +6; позиция +1,+2 в тайлах) → `0x24d70` юниты: сперва трупы (state 0x60, тип<0x1a), затем сетка 24×23 клеток вокруг камеры (−128..+640/+608) с тремя слоями юнитов на клетку + отдельный список летающих (тип 0xb); слой объектов тайла = `BG>>11` (спрайт 0xaf7+n — деревья/камни: это **не** фазы воды); обход строк сверху вниз, в строке справа налево; летающие — тень 0xadf, затем сами → `0x25cbc` снаряды/эффекты (таблицы `0x25cf4` 69 записей и `0x25e08` 20 записей — все обработчики портированы, кроме №58 `0x25f94`: текст урона через `0x29c38`) → `0x2438e` туман (код соседей `0x24446`: бит0 BI; тайлы тайлсета 0..14 — маски, OR в буфер; 15 = разведано) → `0x240c0` рамка протяжки (`[0x3034a]>=2`) → `0x240fb` анимация клика (спрайты 0xaee+, счётчик `0x30370`).
- Обработчики юнитов по типу (`0x250b0`): 0 → ret; 1–13 `0x25151` (в атаке 0x10/0x30 с луком (предмет 5–7) кадр += `0x416c4[type]`; поверх — оружие/щит: кадр = SPR − `0x416b4[type]` + `0x41650[item]`; затем рамка/HP `0x23f44`; отдых 0x20 → «Zz» 0xaea+(ATKCTR>>3)); 14–23 `0x2540a`; 24–25 `0x254b6` (растения); 26–39 `0x2550f` (здания: спрайт `0x416d4[(type−26)*8+slot]` по племени, +1 повреждённое (<½ HP) с огнём 0xae0+счётчик +0x27, руины 0x982+ATKCTR со смещением `0x418cc`, стройка `0x41894`/+2, арсенал 0x1c/0x1d — анимация 0xae6+счётчик +0x28).
- `0x23f44`: 4 уголка по фигуре `0x3d1b8[type]` (6 dword на угол: dx,dy,len по X; dx,dy,len по Y), затем прямоугольник `0x23f18`, полоса HP 4 строки цветом `0x3e3d8[HP]`, длина (w−2)·HP/HPmax (16-битное умножение, байт результата). Цвет рамки `0x3054d[owner]`, 0xfc для текущего выделенного.
- Палитра: RAM `0x44980` (8-бит RGB), DAC получает >>2. Циклическая `0x24132` (главный цикл, каждые 4 BIOS-тика): сдвиг записей 0x49..0x4f и 0x50..0x56 (вода/лава). Портирована (`F[0x24132]`, DAC → `eng.dac`); в тестах не участвует (эталонный `o.step()` главный цикл не вызывает).

## Проверка
`RECT=0,0,512,480 EXCL=80,240,97,263 node js/test/rendertest.mjs traces/render_m0_t0 traces/m0_t0` — область карты совпадает попиксельно на всех кадрах, единственное расхождение без EXCL — программный курсор мыши (x 80..96, y 240..262, 219 пикселей), он рисуется в VRAM при flip (`0x297b5`) — тема следующего агента. rendertest дополнен: RECT/EXCL, отрисовка после каждого тика, сверка пула с `index.json.pool` render-трассы (render_trace.py теперь пишет хеши пула по шагам).
`fixSlotPointers` + `F[0x10b29]` (sprites.js) проверены: загрузка 19 племенных спрайтов для племени 3 из пака 05 совпадает со снимком эталона (таблица слотов и пиксели). Для автономного режима (без снимка) в `js/loader.js` надо вызывать `call(eng, 0x10b29, {eax: tribe})` после загрузки секций (координатору).

## Итог сверки (RECT=0,0,512,480)
- render_m0_t0 (11 кадров): 0 расхождений при EXCL курсора `80,240,97,263`.
- render_m2_t0 (13 кадров), render_m9_t3 (17 кадров): всё, кроме **текста, нарисованного шрифтом `0x29c38` поверх карты**, совпадает попиксельно: счётчик склада еды в (260,0) (`0x2572f`, когда `[0x31c48+owner*4]!=0`), игровое сообщение в (120,380) цветом 0xc4 (`0x2572f`, «My structure is attacked»), плавающие надписи «VP+1/DP+1» над юнитом (снаряд типа 58 → `0x25f94` → `0x29c38`). С `EXCL="80,240,97,263;260,0,350,13"` m2 — 0 расхождений на 13 кадрах, m9 — расходятся только кадры с сообщениями/надписями (100, 125, 375, 400).
- Побочный эффект рендера на симуляцию (+0x42 бит 0) воспроизведён: пул юнитов JS после каждого тика с отрисовкой совпадает с `index.json.pool` render-трассы на всех кадрах трёх миссий (rendertest печатает «ВНИМАНИЕ», если нет — таких строк нет).
