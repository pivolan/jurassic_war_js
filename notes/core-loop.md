# Jurassic War — ядро игрового цикла (pwar.exe V1.05E)

Адреса — виртуальные (образ `pwar.img`, база 0x10000). Имена `FUN_xxxx` — как в `out/decomp_named.c`; поля юнита `U_*` — смещения от 0xe4400 (см. раздел 5). Многие ключевые куски Ghidra не оформила в функции — они читались по asm (`out/asm_states.txt`, `out/asm_move.txt`, `out/asm_unit_handlers.txt`).

## 1. Запуск, main, таймер, главный цикл

**Цепочка запуска.** Точка входа LE 0x286f4 → Watcom-рантайм → `FUN_000101d8` (= main):
1. `FUN_0002b561` ставит обработчик int 24h (critical error); `FUN_0002b91c` — проверка CD (`_PWAR14.TRC`?), при неудаче — "Not found Jurassic war CD-ROM"; при успехе пути `_PWAR03/05/06/08…` переписываются с `.\` на текущий диск.
2. Проверки с фатальными сообщениями через `g_curFileName` + `fatal_msg` (`FUN_0001331c`, печатает строку и выходит): "Please setup" (нет `_SETUP.DAT`/`C:\PWAR.DAT`), "Need VESA" (`FUN_0002ab58`, int 10h AX=4F00), "Need more base/extended memory" (int 31h 0x500 — DPMI free memory, порог 0xdc<<6 = 14 080 KB?), "Need mouse" (`FUN_000290c8` → int 33h AX=0), "Sound card error".
3. Загрузка звукового модуля: `g_curFileName="_PWAR00.TRC"`, `g_curEntryName = DAT_00033650[DAT_00030083]` (0 = MODNULL, 1..3 = MODSB/MODSBPRO/MODSB16 по типу карты в настройках `DAT_00030083`), `res_load` (`FUN_0002b217`, грузит через DPMI в DOS-память, потом вызывается по `FUN_00030c46` — far-указатель на модуль). Модуль = "MOD player for SB" — вся музыка/звук через него.
4. `FUN_0001fb38` — выделение буфера для wave; далее управление уходит в меню `FUN_00020515` и в главный цикл (код 0x100fe, Ghidra его функцией не сделала).

**Таймер.** Своего int 8 нет: используется счётчик BIOS `0040:006C` = линейный адрес 0x46c (`g_timerTicks`, 18.2 Гц). Все "раз в тик" проверки — `if (DAT_xxx != g_timerTicks)`. Настройки скорости: `DAT_00030098` (u16, по умолчанию 1, пишется в `0x20e19` из меню опций; строки "fastest/fast/normal/slow/very slow" @0x398db..) — делитель: игровой шаг раз в N тиков BIOS. Настройка 1 ⇒ ≈18.2 шагов/с. Счётчик обратного отсчёта — младшее слово `PTR_LAB_0003033c` (старшее слово — счётчик прокрутки мышью, `DAT_0003009a`; клавиатурная прокрутка `DAT_0003009c`/`DAT_00030340`). Блок настроек = `DAT_00030083..0x300a5` (звук. карта, IRQ/DMA, скорость игры, скорости прокрутки, режим музыки 0x300a4/a5).

**Глобальные счётчики:** `DAT_00031ab0` — тики BIOS с начала игры; `DAT_00031ab4` — номер игрового шага (используется как источник времени в RNG и для медленных таймеров `&3`, `&0x1f`); `DAT_00031b66 = шаг & 0xf`.

**Главный цикл игры (0x100fe..0x101d0, не функция):**
```
100fe: [303ae]=1 (флаг «в игре»); 26521; 2661c; 23eb1 (отрисовка сцены); 299b4 (flip); 28ef6
10120: loop:
   17e1c  тик симуляции + рендер (см. ниже)
   24132  циклическая палитра (анимация воды, каждые 4 тика сдвигает 2×7 цветов)
   1133c  мышь (события из кольцевого буфера)
   12acd  прокрутка экрана (стрелки/край экрана/правая кнопка)
   10d44  горячие клавиши
   12be6  форма курсора по объекту под мышью + определение края экрана
   20214  музыка (смена трека из _PWAR07.TRC, 14 треков, DAT_00031ac6)
   if [30349]!=0 (код конца партии) or (шаг & 0x1f)==0: call 17728 (проверка победы/поражения); CF → перерисовать всё (100fe)
   if [303b0]!=1 goto loop        ; 303b0 = «партия закончена»
10168: конец партии: 303b0=0, 303ae=0; сеть ([31b69]==1) → 226d9/219ed (обмен результатами); 106b4, 10713 (выгрузка), 20515 (меню) → 100fe
```
`FUN_00023cbc` — это НЕ игра, а демо/attract-цикл: та же последовательность 17e1c/24132, но выход по любой клавише/кнопке или после 600 шагов (`DAT_00031ab4 < 0x258`); запускается из меню после 0xb3 тиков бездействия, карты берутся из `_PWAR10.TRC` ("demo #n", `FUN_00023d72` перебирает 7 демок через `DAT_0003d1a0`).

**`FUN_00017e1c` — тик.** Вызывается каждый проход, реально работает раз в тик BIOS:
```
if (DAT_00036d80 != g_timerTicks):            // новый тик BIOS
  DAT_00031ab0++; countdown(3033c)--;
  if countdown==0:                            // === ИГРОВОЙ ШАГ ===
     countdown = DAT_00030098; DAT_00031ab4++; DAT_00031b66 = шаг&0xf
     FUN_00013f4c   применить очередь приказов (+ сетевой обмен, + редкий спавн артефактов)
     FUN_00015f86   → FUN_00019fbf (авто-реакция: поиск целей / агрессия)
     for u in список юнитов (g_unitListHead → U_NEXT):
        если U_FLAGS5B&1 (мёртв/удалён): FUN_00018058 (обработка трупа/удаление)
        иначе если +0x43 (оглушение/задержка)==0: (*T_HANDLER[U_TYPE])()   // таблица @0x17fb8
        иначе: +0x43 убывает (младшие 2 бита каждый шаг, старшие — раз в 4 шага); если состояние 0x6f → сброс
     FUN_000200fe; FUN_0001ab4c (список снарядов/эффектов, записи @0xf2504, шаг 0x24, next +0x20, диспетчер по типу @0x1ab84 / отрицательные типы @0x1ac98); FUN_0001c340; FUN_00015634
  if (DAT_00030346 != 1 && новый тик):        // === РЕНДЕР (раз в тик BIOS) ===
     26a5c (панель выбранного; для типов 5..8 — магов — ещё 2673d), 242d4, 26498, 24d70 (юниты: раскладка по сетке 24×23 клеток вьюпорта, 3 слоя + отдельный список летающих типа 0xb, отрисовка через таблицу PTR_LAB_000250b0[тип]), 25cbc, 2438e, 240c0, 240fb, 26e77, 2572f, 24843 (мини-карта), 26c0a, 26e62/26e4d, 299b4 (вывод кадра)
```
`DAT_00030346`: 1 = «не рисовать» (в сетевой игре при открытом диалоге симуляция продолжается через `0x21699: jmp 17e1c`). Пауза — отдельный флаг, `FUN_00020bec` (клавиша P).

**Таблица обработчиков по типу юнита (@0x17fb8, 40 записей):** тип 0 → ret; 1..13 (люди и «прирученные» динозавры) → `0x18154`; 14..23 (дикие звери) → `0x184c8`; 24..25 (строители/носильщики) → `0x18568`; 26..39 (здания) → `0x186b3`.

**RNG (`FUN_00020469`):** `N = DAT_00031b58` (модуль задаётся перед вызовом), `seed = DAT_00031b5c`; `t = seed + шаг; result(DX) = t % N; seed += t / N; seed ^= DAT_000393ac[(t/N)>>28]`; счётчик вызовов `DAT_000393a0`. Полностью детерминирован от шага → это основа lockstep-сети: при обмене пакетом 0xf8 сравниваются seed'ы, расхождение = "Running error by line".

## 2. Ввод

**Клавиатура.** Свой обработчик int 9 @0x28c40 (ставится `FUN_00028be0` через DOS 25h, снимается `FUN_00028c19`): читает порт 0x60; `DAT_00044768[scancode]` = 1 пока клавиша нажата (0x60 записей), `DAT_00044708[scancode]` = 1 при нажатии (edge), make-коды кладутся в кольцевой буфер `DAT_000447d0[32]` (head `DAT_000447c8`, tail `DAT_000447cc`). `FUN_00028cce` — есть ли клавиша (ZF), `FUN_00028cdd`/`FUN_00028d11` — взять скан-код, `FUN_00028c9d` — очистить всё. Модификаторы читаются прямо из массива состояния: LShift 0x44792, RShift 0x4479e, Ctrl 0x44785, Alt 0x447a0.

**Горячие клавиши в игре — `FUN_00010d44`:** таблица `PTR_LAB_00010d74[scancode]` (0x60 записей; несвязанные → 0x10d71 ret). Если нажат модификатор и идёт набор чата (`DAT_000333c9`) → `FUN_00010f83` (ввод текста, ENTER = отправить в сеть через `FUN_00014c0d`).
| клавиша | обработчик | действие |
|---|---|---|
| ESC, F10 | `FUN_00020acb` | игровое меню |
| F1 | 0x1127e → `FUN_00020ee5` | помощь (не в сети) |
| F2 | 0x112a1 → `FUN_000237e4` | сохранить (`_PWARSAV.000`, только одиночная) |
| F3 | 0x112af → `FUN_00023590` | загрузить |
| F4 | `FUN_00020c54` | опции |
| F5–F8 | 0x112e8 | перейти к сохранённой позиции экрана `DAT_00031b08[k]`; с Ctrl — запомнить |
| P | `FUN_00020bec` | пауза (в сети шлёт 0xfb → у соперника "Pause by opponent") |
| TAB, W | `FUN_00026510` | окно информации |
| ` | `FUN_00024525` | переключение режима мини-карты |
| SPACE | 0x1103e → 0x1113c | центрировать экран на выбранном |
| PAD+ | 0x11025 | показ характеристик (`DAT_00031ac8` toggle, таймер 0x1f) |
| N | 0x11207 | следующий свой юнит (циклически), выбрать и центрировать |
| A / Z / G | `FUN_00013237(2/3/4)` | команды «идти/атаковать», «отдых», «охрана» |
| 0–9 | 0x1107b | выбрать группу n; Ctrl+n — назначить группу; Alt+n — выбрать и центрировать; Shift — добавить/убрать |
| ENTER | 0x10fbc | чат (сетевая игра), буфер `DAT_000335ca` |
| PrtScr (0x37) | `FUN_000275b4` | скриншот (`_PWAR000.PCX`) |
В коде рядом лежат неподключённые отладочные читы: 0x10ef4 — `+1000 еды` локальному игроку, 0x10f05 — `+1` к HP/HPmax/ATK(+2)/MP/MPmax/SPD выбранного юнита; ссылок на них нет (мёртвый код).

**Мышь.** Драйвер через int 33h (обёртки @0x29a14..: 0=reset, 1/2 show/hide, 3 pos, 4 set pos, 7/8 границы, 0xf чувствительность, 0x1a/0x1b, 0x10 exclusion, 0x14 swap handler). События приходят в кольцевой буфер записей по 0x14 байт `DAT_000450e4[32]` (поля: маска событий, X, Y, +0x0c/+0x10 = сырые координаты драйвера); текущее положение `DAT_00045098/0x4509c`, кнопки `_DAT_000450a8`, флаг движения `DAT_000450ac`. `FUN_000292ac` вынимает событие → `_DAT_000450c8` (маска), `DAT_000450cc/d0` (X,Y), `DAT_000450d4/d8`.
`FUN_0001133c` — диспетчер в игре: бит 2 → ЛКМ нажата `FUN_000114f1`, бит 4 → ЛКМ отпущена `FUN_00011672`, бит 8 → ПКМ нажата `FUN_0001188c`, бит 0x10 → ПКМ отпущена `FUN_0001194c`, движение → `FUN_000113a5`.
Раскладка экрана 640×480: вьюпорт карты x < `DAT_000488c4` (=0x204=516), правая панель 516..640; мини-карта в прямоугольнике `DAT_00030388..0x3039c` (обычно 516..636 × 4..124, масштаб 1 или 2 тайла/пиксель, флаги `DAT_00031ae0`: 1 = «большая карта», 4 = зум ×2, 8 = показана; переключение кликом в углу ≥(616,456)); панель имеет две страницы (`DAT_00031ae4`: 0 = юнит, 1..14 = здание типа 26+): таблицы кнопок `DAT_00030c64` (28 прямоугольников: строка команд 3×3 при y=135..249, инвентарь 12 слотов 3×4 при y=262..419, мелкие кнопки y=424..445, полоса y=446..474) и `DAT_00030d44` (17 кнопок здания), диспетчер ЛКМ `FUN_000120c0` → `0x12148`, ПКМ `FUN_00012214` → `0x1227c`.
- ЛКМ нажатие: на мини-карте → `FUN_00012a4e` (прыжок экрана); в поле → запоминаются координаты, `DAT_0003034a`=1; движение > 12 px → `DAT_0003034a`=2 = рамка (`FUN_000113a5`).
- ЛКМ отпускание: рамка → `FUN_000119dd`: выбираются свои живые юниты (owner == `DAT_00031b64`, тип < 26) в прямоугольнике, `U_f07 |= 0x80`; «лидером» (`DAT_00031adc`) становится юнит с максимальной суммой HPmax+MP+ATK+DEF+SPD; Shift — добавить к выделению. Без рамки → таблица режимов курсора `PTR_LAB_0001179c[DAT_00031aca]` (16 режимов): 0 — обычный выбор (`FUN_00011c13`: `DAT_00031adc`=юнит, панель по типу), остальные — выдача приказа (см. §3).
- ПКМ: над мини-картой — переключение режимов карты (`DAT_00031ae0`); при активном режиме курсора — отмена (`DAT_00031aca`=0); в поле над своим юнитом/зданием — `FUN_000119c1` + контекстный режим («Drop», «Attack» — курсор меняется в `FUN_00012be6`); правый drag (`_DAT_000450a8&2`) — прокрутка карты на 32 px за единицу движения.
Камера: `DAT_00031ae8/DAT_00031aec` (пиксели, кламп `DAT_00031b00/b04`), вьюпорт `DAT_00031af0×DAT_00031af4` тайлов; край экрана → `DAT_0003037c` биты (8 лево, 2 право, 1 верх, 4 низ) → `PTR_LAB_0003390c[биты]`.

## 3. Приказы, очередь и машина состояний

**Очередь приказов** (единая для игрока, ИИ и сети — основа детерминизма): записи по 10 байт с `DAT_00033c88`, указатель конца `PTR_DAT_00033c7c`:
`[0]` = маркер игрока (`DAT_000333c0`, в сети чей приказ), `[1]` = код приказа, `[2..3]` = индекс юнита (u16), `[4..5]` = цель (индекс юнита), `[6..7]` = X, `[8..9]` = Y.
Добавление — `FUN_00014895(al=код, si=юнит, di=цель, dx=X, bx=Y)`; в сети дополнительно суммируется контрольная сумма `DAT_00033c86` и байты уходят в COM-порт (`FUN_000148fe`). Применение — в начале шага `FUN_00013f4c`: для каждой записи, если юнит не умирает (`+0x46 != 0x6f`, состояние не 0x6f/0x60), пишется **отложенный приказ**: `+0x46` = код, `+0x47` (dword) = цель, `+0x4b/+0x4d` = X,Y. Два прохода (сначала чужие, потом свои или наоборот по `DAT_000333c0`) — одинаковый порядок на обеих машинах. Там же раз в 32 шага с вероятностью 51/10000 на случайный тайл ставится артефакт (item 0x0f+rand(15)) с сообщением "--- Appear the Celestial Sword ---" и т.д. (`FUN_0001cdf3`).
Сетевой приём `FUN_00014942` (опкоды 0xf0..0xff: 0xf6 сброс очереди, 0xf7 обмен очередями, 0xf8 конец шага + сверка RNG-seed, 0xfb пауза, 0xfc чат, 0xfd выход соперника, таймаут 0x8f тиков → "Communication line bad").

**Выдача приказа из UI.** `FUN_000129cb(al=код, esi=цель, edx=X, ebx=Y)` кладёт «ожидающий клик-приказ» (`DAT_00031acc..ad8`), далее он рассылается всем выделенным (`U_f07&0x80`) через очередь. Режимы курсора `PTR_LAB_0001179c`: 1 → 0x0f (идти в X,Y), 2 → 0x1f (атаковать юнит под курсором, `FUN_000130c6` — поиск по хит-боксам `DAT_00033978[тип*8]`), 3 → 0x2f (отдых), 4 → 0x3f (охрана), 5 → 0x4c (добывать/охотиться в точке), 6 → 0x51+слот (отнести предмет из слота `+0x51` цели: склад/арсенал/юнит), 9..13 → 0xa0..0xa4 (заклинания на цель; 0xa4 требует свой труп в состоянии 0x60 — воскрешение, `0x11e6a`), 15 → 0xa6; ещё 0xa7/0xa8. Кнопки команд панели → `FUN_00013237(k)`: проверяет бит k в маске способностей юнита `+0x17` (dword, у людей/зверей 0x3f) через `FUN_00014873(бит)` и уходит в `PTR_LAB_00013298[k]`; иначе звук «нельзя» `FUN_0001fd8b`.

**Применение отложенного приказа** (в обработчике типа 0x18154, только когда юнит стоит ровно на тайле `X&0x1f==0 && Y&0x1f==0`): код приказа становится **состоянием** `+0x2b`, параметры копируются `+0x47→+0x33` (цель), `+0x4b→+0x37`, `+0x4d→+0x39` (точка назначения); для групп 0x1x/0x2x ещё обнуляется счётчик анимации `+0x4f`. Коды ≥0xe0: 0xe0 — как обычный приказ; иначе (0xe1 «использовать/надеть предмет из слота +0x47») выполняется сразу `caseD_e1` (0x19bbe, таблица @0x19ee4 по слоту).

**Диспетчер состояний** (0x18185): по старшей тетраде `+0x2b` через таблицу @0x182a8; ≥0x80 — @0x182c8. Перед ним каждый шаг — `FUN_000163e4` (регенерация маны магов от тотемов-зданий 0x11/0x1d/0x13/0x14, авто-цели, решения ИИ) и раз в 16 шагов `FUN_00018ab2` (регенерация: HP+1 если < max — у людей только когда `HP&3==0` и `FUN_0001c6e9` даёт разрешение; MP+1; **баг оригинала:** при переполнении MP в `0x18b2e` ограничивается HP, а не MP).

| состояние `+0x2b` | группа | смысл (по коду) |
|---|---|---|
| 0x0f → 0x00 | движение | приказ «идти»: `FUN_0001db94` строит путь (для ИИ с шансом бит-26 при дистанции >0x13f px — `FUN_0001a393` телепорт/прыжок), 0x00 = идём (`FUN_0001dc43`); по прибытии тип 4 (human4) → `caseD_e0` 0x1d1cf; счётчики по роли `+0x08` (1 → `0x32b6c[игрок]`, иначе `0x32bbc`), `+0x52`++ → `FUN_0001a773` (кадр стойки), затем 0x3f |
| 0x1f, 0x10, 0x11, 0x12 | атака | 0x1f — старт; 0x10 — подходим к цели (`+0x33`), точка = центр цели по `T_SPR_CX/CY`, направление `FUN_0001a95d`+`FUN_0001aa10` → `U_DIR`; 0x11 — идём к тайлу цели; 0x12 — удар и перезарядка: `+0x2c = 16 − SPEED>>4` шагов (`0x18da3`), затем снова 0x11/0x10. Цель мертва/труп (0x60/0x6f) → 0x3f. Дикие звери 14..23, попав в 0x1x с вероятностью 1/200 (rand 0xc8 == 0x64) «передумывают» |
| 0x2f → 0x20 | отдых (Z) | раз в 32 шага: звук 0x0d (если `+0x42`&1==0), HP+1, MP+1; выход, когда HP и MP полные (`FUN_000163e4` case 2) |

## 4. Победа/поражение

`FUN_00017728` (раз в 32 шага): одиночная игра — `FUN_00017d5f`: если у локального игрока нет живых юнитов → `DAT_00030349`=1 (поражение); `FUN_00017861` — сценарные условия: таблица `PTR_FUN_00036a60[миссия*8 + игрок]` (`DAT_00031abb` — номер миссии 0..11 в кампании племени) — по функции на миссию ("Acquire food over 3000" и т.п.). Коды `DAT_00030349`: 1 поражение, 2/3 победа (экраны GRPEND/WIN из `_PWAR09.TRC`, брифинг следующей миссии `FUN_00014c90`, `FUN_00015278`), 4 «Communication line bad», 5 «Running error by line». `DAT_000303b0`=1 → выход из цикла.

## 5. Структура записи юнита

Пул: 576 записей × 100 байт (0x64) в памяти от 0xe4400 (индекс = байтовое смещение, 0 = «пусто»; следующая область 0xf2504 — снаряды). Секция карты **OB (57600 байт) = дамп этого пула** (запись k → байты k*100..; поля со сдвигом 8 — дамп начинается с 0xe4408), **OI (8000) = пул предметов на земле** 500×16 (записи 0xf4f34), **OM (10800) = пул снарядов/эффектов** 300×36. Живые юниты — двусвязный список `g_unitListHead`(0x31b6c) через `+0x60` next / `+0x5c` prev; свободные — `DAT_00031b70`; `FUN_0001aaac` — взять, `0x1aaf7` — пометить мёртвым и вернуть.
