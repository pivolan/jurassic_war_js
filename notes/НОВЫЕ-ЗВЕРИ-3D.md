# Новые звери через 3D-модель: рецепт (по опыту демона, 04.10.2026)

Демон (тип 18) сделан так: 3D-модель в Customuse → анимация в Blender (мокап + ручные позы) → съёмка кадров →
палитра игры → пак `reimpl/data/beasts.bin`. Скрипты — `tools/звери3д/` (рабочие копии и файлы моделей — `out/новые_звери/модель/`), сборщик пака —
`tools/пак_зверей.py`, подстановка кадров в движок — `reimpl/js/port/новые_звери.js`. Ниже — порядок и все
правила, на которые мы наткнулись. Повторять для нового зверя в том же порядке.

## 1. Модель (Customuse, ~180–250 кредитов)
- Из CLI: `tools/звери3д/cu.mjs <инструмент> '<json>'` (внешний сервис Customuse, токен — свой), цепочка целиком —
  `цепочка.py <узел-лист> <имя> "<описание текстуры>"`.
- Лист персонажа по канону: Nano Banana Pro Edit (~20). **Упрощать под пиксели**: крупные формы, мало мелочей,
  3–4 цветовых пятна, но рисовать как гладкий 3D-рендер (не пиксель-арт — по плоской картинке модель выходит плохо).
  Без «голого» вида: одежда/пластины брони (владелец: демон не должен выглядеть стриптизёром).
- `imageToMultiview` с A-pose (~27) → `tripoP1Mesh3d` multiview, faceLimit 12000 (~100, **без текстуры**) →
  `textureGeneration` meshy-7-retexture multiview, base color (~26) → `autoRigging` cartwheel biped (~8).
  CR1/CR1.2 multiview не умеют (ошибка, кредиты не списываются).
- Скелет: 52 кости с именами SMPL (pelvis, spine1–3, neck, head, left_/right_ collar/shoulder/elbow/wrist,
  hip/knee/ankle/foot, пальцы). Модель со скелетом приходит **ростом ~100 единиц**, без скелета ~1.

## 2. Анимация (Blender 5.2, локально; мокап — открытые библиотеки (Bandai Namco CC BY-NC, CMU))
- Перенос мокапа: `перенос.py модель_rig.glb клип.bvh auto N выход.blend` (способ робота K-01: анатомические
  кадры костей). Ось кости цели — «сустав → следующий сустав»; у головы — «шея → голова» (своя ось в файле врёт).
- **Шаг под скорость игры.** Любой юнит проходит 4 px за такт; у зверей 4 кадра шага по 2 такта → цикл 8 тактов
  = **32 px**. Замер: `замер_шага.py рост сырая_высота`. Естественные походки дают 51–63 px → копыта скользят,
  «скачет». Лечится `STRIDE=0.55` (сжатие размаха ног/рук к среднему). Демон: walk_masculinity, STRIDE 0.55 → 31.7 px.
- **Удар.** У зверей 3 кадра удара по 2 такта, **урон — на кадре 2** (`combat.js` 0x1a7cb, таблица 0x36ebc).
  Значит порядок: подготовка → замах → УДАР (лапа на цели). Протяжка после удара в кадр 2 нельзя — выглядит
  как отшатывание. Мокап (punch/slash/kick) не подошёл — удар ставим вручную: `удар_лапой.py` (позы через
  «навести кость на направление» + поворот/наклон корпуса + выпад таза), кадры задаются `ATTACK_FRAMES=301,302,303`.
- Смерть: 2 кадра на «север» и «юг». На север — навзничь, на юг — **ничком** (навзничь от камеры сверху выглядит стоящим).

## 3. Съёмка кадров (`спрайты.py <ход|стойка|удар|смерть> папка`)
- Камера ортографическая, **наклон 60°** над горизонтом (как у зверей оригинала), смотрит на север.
- 5 направлений: 0 север (спиной), 1 СВ, 2 восток (профиль вправо), 3 ЮВ, 4 юг (лицом). 5–7 игра рисует зеркалом 3–1.
- Ходьба/стойка — камера следует за тазом (на месте); **удар — камера стоит** по тазу первого кадра, иначе выпад не виден.
- Каждый кадр пишет в `якоря.json` точку земли под тазом (для выравнивания).
- `matrix_world` после сброса пересчитывать (`view_layer.update()`), иначе центр кадра от прошлого кадра.

## 4. Перевод в игру (`в_игру.py сырые выход рост`)
- Рост стойки с юга: **38 px** (люди 40–46; 64 было «слишком большой», 42 — всё ещё крупно).
- Перед палитрой: насыщенность ×1.7, яркость ×1.25 — иначе красная кожа уходит в коричневый.
- Палитра MAIN.PAL без индексов 0, 1 и 0xc0–0xdf. Якоря пересчитываются в пиксели кадра.

## 5. Пак (`tools/пак_зверей.py демон=папка`)
- Рамка выделения у всех типов — клетка 0…31. **Ноги должны стоять внутри рамки** (владелец: «у всех юнитов ноги
  в рамке»). Привязка: стойка направления — центр кадра по горизонтали в 16, точка земли под тазом на
  `FEET_Y=24`; остальные кадры направления — по той же точке земли (иначе вынесенная лапа сдвигает тело назад).
  Проверка численно: низ тела (без тени, индекс > 1) должен быть ≤ ~33.
- **Тень прямо вниз** (сдвиг (0, 5)) во всех направлениях: зеркальные направления отражают кадр вместе с тенью,
  тень со сдвигом влево уезжала там вправо.
- Не центровать по кадру тираннозавра — он крупный, зверь уезжает из рамки.

## 6. В игре
- Кадры грузятся только по ссылке `?demon=1` (`beasts.bin?t=` без кэша); в обычную игру новые звери не входят.
- Свой зверь управляется: курсор «идти» для зверей игрока (`input.js`, 0x12be6) — в оригинале звери всегда дикие.
- Проверка: Playwright — юниты в 8 направлениях с рамками (`направления.mjs`), видео из игры по тактам,
  сравнение с человеком. После правки game.js — открыть страницу и убедиться, что грузится.

## 7. Эпичный удар (демон, 04.10)
- Владелец: взмах одной лапой «не мощно», прыжок «слишком скомкано в три кадра». Выбран **молот**: лапы в замок,
  замах над рогами, обрушение вниз перед собой с приседом — `tools/звери3д/удар_молот.py`.
- Эффекты рисуются в СЫРЫХ кадрах до перевода в игру (`эффекты_удара.py`): огонь на кистях в замахе и ударе,
  короткий толстый огненный след у лап (длинная дуга в 38 px выглядит плетью), раскалённые трещины (тёмные с
  оранжевой серединой — просто тёмные не видны) и пыль. Точки лап/земли пишет `спрайты.py` в якоря.json.
- Трещины и пыль потом убраны (владелец: лапы земли не касаются, тень взрыва — «парит»); остались огонь на лапах и след. Включить: GROUND=1.

## 8. Тень и показ (04.10, поздние правки)
- **Тень — настоящая проекция**: второй проход Cycles в `спрайты.py` (модель невидима для камеры, плоскость-ловушка
  на полу), свет **почти отвесный** `(0, −0.08, −1)`: тень компактно под ногами, как у людей, и при зеркале
  (ЮЗ/З/СЗ) не меняет сторону. Боковой свет давал тень, которая «поворачивалась» с демоном. В игре тень — индекс 1;
  сборщик пака свою тень не добавляет, если в кадре уже есть индекс 1. По горизонтали центрируем ТЕЛО (якорь под
  тазом в x=16), не кадр — кадр с тенью шире.
- **Удар до земли**: в кадре удара двухзвенная ОК (`ик()` в `удар_молот.py`): ноги держат ступни на месте при
  приседе, лапы — в точку на земле перед копытами. Руки у модели короткие (0.36 роста) — нужен наклон 90° и
  присед 0.40 (`LEAN`, `CROUCH`); скрипт печатает высоту кистей над полом.
- **Листы для владельца** (`tools/звери3д/лист.py кадры удар|ход|смерть выход.png`): строки — направления
  (С, СВ, В, ЮВ, Ю, ЮЗ, З, СЗ), столбцы — время, первый столбец — стойка, подписи шрифтом Noto (у PIL по умолчанию
  нет кириллицы).
- Пыль под бронтозавром убрана (владелец 05.10: «плохо смотрится»). Механизм индекса 64 в блиттере остался; слой пыли — tools/звери3д/эффекты_пыль.py, не запускать без спроса.
- Бронтозавр: выбран удар «мини-дыбы, вариант 3 — низко, длинный выпад» (дыбы10.json[2], кадры 521–523 в бр_дыбы.blend).

## 9. Бронтозавр, итог (05.10)
- Мультяшный первый вариант заменён: лист по образцу спрайтов игры (Nano Banana Pro Edit, вторым входом — рекс и
  мамонт из игры), выбран **А** — серо-оливковый, морщинистая кожа. Модель `бронтоА_rig.glb`, скелет Tripo quadruped.
- Анимация — `tools/звери3д/четвероногий.py`: кости по ГЕОМЕТРИИ (ступни → цепочки ног, путь к самой передней
  кости — шея после плечевого пояса, к задней — хвост; общий ствол хвостом не считается). Имена у Tripo врут.
  `NECK` — укорот шеи масштабом звеньев, `NECK_UP` — подъём у основания. Удар — мини-дыбы 3, хвост противовес.
- Для природных цветов `SAT=1.15 BRI=1.1` в `в_игру.py` (×1.7 по умолчанию — только для красного демона).
