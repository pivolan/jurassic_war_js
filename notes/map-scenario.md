# Jurassic War — карта, сценарий, победа (реверс, 2026-09-07)

Источники: pwar.exe (образ pwar.img, база 0x10000), out/decomp_named.c, паки _PWAR08 (96 карт кампании), _PWAR10 (7 демо/сейвов), _PWAR13 (20 карт), _PWAR09 (тайлсеты, брифинги).

## 1. Загрузка карты = снимок памяти (FUN_00010739 @0x10739)
`FUN_00010739(mapIndex, packName)` грузит 9 записей `mapIndex*9 + k` через FUN_0002b190 (res_seek+res_read, EDI = адрес назначения, ECX = размер) прямо в глобальные структуры игры. Карта — это **дамп памяти** движка (поэтому у демо-карт имя «demo save»):

| k | секция | адрес в памяти | размер | что это |
|---|---|---|---|---|
| 0 | SI | 0x31a90 | 30 | строка-имя сценария (ASCII, редакторская: «48*48-tile0-grp1-st1», «501_0_t», «demo #2») |
| 1 | GI | 0x31aae | 7072 | **блок глобальных переменных игры** 0x31aae..0x3364d (см. §4) |
| 2 | OB | 0xe4404 | 57600 | **массив юнитов**: 600 записей × 96 байт (§3) |
| 3 | OI | 0xf4f34 | 8000 | список объектов на земле: 500 записей × 16 байт (§5) |
| 4 | OM | 0xf2504 | 10800 | пул снарядов: 300 записей × 36 байт (§6) — в файле мусор/остатки |
| 5 | BI | 0x10ce74 | 45056 | сетка 256×176 байт: туман войны + занятость (§2) |
| 6 | EV | 0x31b88 | 160 | кусок внутри GI (0x31b88..0x31c27); во всех 123 картах нули, в коде не читается кроме load/save (@0x10838, @0x10a99) — резерв |
| 7 | BG | 0xf6e74 | 90112 | сетка тайлов u16 256×176 (§2) |
| 8 | MO | 0x117e74 | 45056 | сетка 256×176 байт: занятость юнитами (§2) |

Индекс карты кампании = `mission*8 + tribe` (12 миссий × 8 племён). Текущая миссия — `DAT_00031abb` (0..11), племя/игрок человека — `DAT_00031b64` (0..7). Брифинг: пак 09 запись `0x50 + mission*8 + tribe` (T01_1.TXT = миссия 1, племя 1); картинка сюжета `ST-xx` = запись `0x0e + mission*2`; после 12-й миссии `DAT_000303b0=1` (кампания пройдена). Племена по индексу владельца: 0 Tyrano, 1 Ka-Noo-Se, 2 Romack, 3 Masai, 4 Moospell, 5 KoomBa, 6 RaDumBa, 7 KoaKa; **владелец 8 = дикая природа** (нейтральные звери).

Мини-загрузчик после секций: FUN_00010b29 (по `DAT_00031b64`), FUN_00010b74, FUN_00026521 — подготовка палитры/тайлсета; FUN_00015070 очищает BI/MO и заново штампует занятость всех живых юнитов; FUN_00015127 сбрасывает поле +0x17 (=0x3f) у юнитов типов <14.

## 2. Сетки: BG, BI, MO, проходимость
* **BG** (0xf6e74): `u16[y*256+x]`, биты 0..10 — индекс тайла (591 тайлов 32×32 в TILEn.TRT), биты 11..15 — **фаза анимации воды** (значения 1..7 встречаются только на тайлах воды/берега, напр. tile0 #130–136, tile2 #391–406); при отрисовке (@15085) попадают в таблицу 0x40500 по экранным клеткам. Для клика/проходимости тайл с ненулевыми старшими битами считается непроходимым (`if (v & 0xf800) return`).
* **Проходимость** тайла: таблица `DAT_0003183c[tileIdx]` (596 байт, в EXE все = 1, заполняется при загрузке тайлсета), бит0 = проходимо (@0x1e5xx: `CONCAT11(hi, DAT_3183c[tile]) & 1`, затем `BI & 0xfc != 0` → занято). Летающий тип 11 (ptero) проходит всё (@9005).
* **TILEn.INF** (591 байт) → копируется в `DAT_0003e8aa[tile]` и используется как **цвет/класс мини-карты** (@14852): 0, 1, 5 (в tile0: 5 = тайлы 0..19 и берег/вода-переходы). Не проходимость.
* **BI** (0x10ce74, байт на клетку): бит0 = **клетка разведана (туман войны)** — в файле карты 0 стоит только вокруг стартовых юнитов игрока (радиус ~3); бит1 = **на клетке лежит объект OI** (FUN_0001c340 ставит, при истечении срока FUN_0001c370 снимает); биты 2..7 = **владелец+1 юнита/здания, стоящего на клетке** (0 = пусто; 9 = дикое животное; 1 = игрок 0). Все проверки «занято» — `BI & 0xfc`.
* **MO** (0x117e74): старший ниббл = владелец+1 стоящего юнита (используется при поиске цели/клике: `(MO>>4)-1 == owner`), младший ниббл = служебный признак/счётчик занятости (`MO & 0xf != 0`). В файлах карт почти всегда 0 — движок перештамповывает при загрузке.
* Штамповка: мобильные юниты FUN_0001a3db (@8951: MO=(MO&0xf0)|b; BI=(BI&3)|(owner+1)<<2; MO=(owner+1)<<4|b), здания FUN_0001dac2 (@5815: BI=(BI&3)|(owner+1)<<2, MO=(MO&0xf)|(owner+1)<<4, на весь футпринт). Хитбокс юнита для клика: таблица 0x33978[type*8] (4×i16: dx0,dy0,dx1,dy1).
* Размер карты: `g_mapW`=0x31af8, `g_mapH`=0x31afc (u32, тайлы); камера `0x31ae8/0x31aec` (пиксели), максимум камеры `0x31b00/0x31b04`.

## 3. Запись юнита (96 байт; смещения от начала записи; в коде поле = ESI + 0xe4404 + off)
| off | тип | поле |
|---|---|---|
| +0 | u8 | тип (1..25 мобильные, 26..39 здания; 0 = свободная запись) |
| +1 | u8 | индекс игрока для статистики (U_PLAYER_IDX5) |
| +2 | u8 | владелец 0..7, 8 = природа |
| +3..+6 | u8 | состояние/приказ (+3 бит7 = выделен), +5 = очки инвентаря? |
| +7 | u8 | STAT0B (23/11/1/0 по типу — темп/дальность?) |
| +8 | u8 | HP max |
| +9 | u8 | MP |
| +0xa | u8 | HP |
| +0xb | u8 | ATK |
| +0xc | u8 | DEF |
| +0xd | u8 | MP max |
| +0xe | u8 | скорость |
| +0xf | u16 | **еда при юните** (у людей старт 30; у зверя = добыча при охоте; у склада = запас). Инициализируется из T_STATS_COST |
| +0x11 | u8 | 0xff |
| +0x12 | u8 | предмет в руках (0xff нет) |
| +0x13 | u32 | таймер/маска (0x3f) |
| +0x17..+0x21 | u8×11 | **инвентарь**: 3+3+3+2 слота (проверяются миссией 5) |
| +0x27 | u8 | состояние анимации (0x38 стоит, 0x30 идёт, 0x60 умирает, 0x6f …) |
| +0x2b | i16 | X (пиксели) |

Голова списка живых юнитов `g_unitListHead` = 0x31b6c (в GI +0xbe), свободных — 0x31b70. Стартовая расстановка карты = содержимое OB по этому списку. Примеры: карта 0 (миссия 1, Tyrano): 4 human1 игрока + 25 зверей (18 brown_beast, 4 tiger, 3 wolf); карта 40 (миссия 6, Tyrano): игрок 7 юнитов, противник Ka-Noo-Se 101 (67 human5, 12 bldg30 …), природа 89.

## 5. OI — объекты на земле (16 байт, база 0xf4f34)
+0 тип (1..14 = **труп зверя/человека** данного типа = еда; 15..29 = **предмет** «Celestial Sword … Skull Stick» (15 = Celestial Sword, 16 = Moonlight Sword, 17 = Mystical Liquor, 18 = Ax of Darkness, 19 = Rock crystal, 20 = Dragon's Eye, 21 = Moon Shield, 22 = Hammer of Darkness, 23 = Volcano Spear, 24 = Sun Shield, 25 = Leather Shoes, 26 = Bone Necklace, 27 = Bone-Bracelet, 28 = Gloves, 29 = Skull Stick); **30 = вечный объект** (не гниёт)); +1 tx; +2 ty; +4 i16 счётчик A (уменьшается раз в 128 кадров для типов ≤14 — гниение трупа); +6 i16 счётчик B; +8 prev; +0xc next. Списки 0x31b7c/0x31b80. Категория предмета → `T_CLS_FLAGS[T_TYPE_CLS[type]]` биты 1/2/4 → в какой из 4 групп инвентаря кладётся (FUN_000170f6/FUN_000171d3). В картах кампании OI пуст (только у карты 40 6 остаточных записей).

## 6. OM — снаряды (36 байт, база 0xf2504)
+0 номер спрайта (тип снаряда + направление), +1 время жизни, +2 флаг, +4 стрелок, +8 цель, +0xc/+0xe X/Y, +0x12.. расстояние, +0x18/+0x1a скорость dx/dy (таблица направлений DAT_00030504 ×2), +0x1c prev, +0x20 next. FUN_0001bffc создаёт снаряд, цель = центр спрайта цели (T_SPR_CX/CY). В файлах карт — мусор.

## 7. Победа / поражение
Каждый кадр логики (FUN_00017728 при DAT_00031b69≠1): 
1. FUN_00017d5f — если у игрока `DAT_00031b64` нет живых юнитов → `DAT_00030349 = 1` (**поражение**).
2. FUN_00017861 — вызов обработчика цели миссии из **таблицы PTR_FUN_00036a60[mission*8+tribe]** (96 указателей, 26 уникальных). Результат 2 = **победа**.
3. Победа → FUN_00015278 (сюжетный экран ST-xx, mission++, FLI из таблицы 0x356aa), поражение → экран DEFEAT (пак 09 записи 0x4e/0x4f) и повтор брифинга FUN_00014c90.
Сетевые коды результата: 4 = таймаут/«Oppnent is game aborted», 5 = рассинхрон 0x31b5c.

Цели миссий (tribe = индекс племени игрока 0..7):
| миссия | условие победы |
|---|---|
| 1 | сумма поля «еда» (+0xf) по живым юнитам игрока ≥ 3000 (FUN_00017989). Племя 6 (RaDumBa) дополнительно: уничтожить все юниты владельца 0 (Tyrano) |
| 2 | построить здания (FUN_00017879 считает живые достроенные здания игрока по типу): tribe0: 3×тип27 + 3×тип35; tribe1: 2×27 + 2×31; tribe2: 2×34 + 4×30; tribe3: (28+29)≥4 и 27≥3; tribe4: 27≥3 и 32≥3; tribe5: 27≥3 и (28+29)≥2; tribe6: (28+29)≥3 и 30≥4; tribe7: 37≥3 |
| 3, 4 | уничтожить все юниты конкретного владельца (FUN_000178e7 → u16[8] @0x36bf0): tribe0→владелец 1, 1→0, 2→3, 3→2, 4→5, 5→4, 6→7, 7→6 |
| 5 | любой живой юнит игрока держит в инвентаре (слоты +0x17..+0x1c, +0x20..+0x22) предмет из таблицы 0x36c54[tribe] = [15,17,20,22,19,21,23,16] (Celestial Sword, Mystical Liquor, Dragon's Eye, Hammer of Darkness, Rock crystal, Moon Shield, Volcano Spear, Moonlight Sword) |
| 6 | **захватить** вражеское святилище (тип 26) — запись из таблицы 0x36c5c[tribe] (смещение в OB); если она уничтожена → поражение |
| 7 | не осталось живых юнитов типов 14, 16, 17, 19 (raptor, green_dino, red_dino, mammoth) у кого бы то ни было (FUN_00017947 → u16[40] @0x36c04) |
| 8 | захватить два святилища из таблицы 0x36c7c[tribe]; гибель любого → поражение |
| 9–12 | уничтожить все юниты всех остальных племён (`cntByOwner[i]==0` для всех i, чьё племя ≠ игрока) |
Побочные: 0x36c04 = cntByType (u16[40]), 0x36bf0 = cntByOwner (u16[8]), 0x36bc4+type+2 = счётчик зданий игрока по типу.

## 8. Тайлсеты, OB/OI/OM «одинаковые для тайлсета»
Прежний вывод неверен: OB/OI/OM не зависят от тайлсета, это просто похожие снимки памяти редактора (у карт 0 и 1 разные OB). Тайлсет выбирается строкой SI («tileN»); все 7 тайлсетов — 591 тайл 32×32 в одинаковой раскладке (общая таблица проходимости 0x3183c).

## 9. Рендеры
out/img/map000_full.png, out/img/map040_full.png — тайлы + стартовые юниты из OB (кадр стойки по направлению; здания — приближённо спрайтами 2432+). Статичных объектов (деревьев/камней) в BI нет — они лежат в **старших битах BG** (биты 11..15 = индекс декорации 1..7, спрайт пака 04 №2807+индекс, клетка непроходима); см. GAME-LOGIC §8.2 и `notes/movement-spec.md` §3. Пак 05 (128×128 и др.) — крупные декорации/панели, к сетке карты не привязаны.

## Осталось непонятным
* Точное назначение младшего ниббла MO и поля +0x27/+0x4c записи юнита (состояния анимации/приказов — тема «ядро/приказы»).
* Соответствие типов зданий 26..39 названиям (Sanctuary = 26 точно: цели миссий 6/8; остальные — Food-storage, Armory, казармы племён — по спрайтам 2432+ и таблице тренировки).
* Плотная область GI +0x180..+0x1b80 (переменные ИИ): структура полей — тема «ИИ».
* Как из карты выбирается стартовая еда 0 у игрока при 1000 у ИИ (в картах миссии 1 у человека food=0 — вероятно, редактор).
* Значения BG-флагов 1..7 предположительно фазы анимации воды; отрисовку слоя (таблица 0x40500) не читал до конца.
