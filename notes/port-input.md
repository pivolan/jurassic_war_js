# Порт ввода и UI-логики (тема input)

Файлы: `js/port/input.js` (функции оригинала, реестр F), `js/input.js` (адаптер браузер → память оригинала), `cases_input.py` (генератор кейсов), `js/test/inputtest.mjs` (как fntest, но игнорирует память, которую пишут ещё не портированные функции рисования). Отчёт о сверке: `node js/test/inputtest.mjs cases/inp_*` → **87 ok / 6 fail**; шесть падений — только прокрутка 0x12acd, где расхождение исключительно в состоянии отрисовщика сцены (0x23eb1 ещё не портирован: строка статуса 0x4191c/0x4191e, буфер фона под курсором 0x466fc…), собственные эффекты прокрутки (камера 0x31ae8/0x31aec, метки времени 0x30342/0x33860/0x3033e) совпадают. Все чужие кейсы (fntest) при подключённом input.js по-прежнему проходят.

## Структуры драйверов (для адаптера)
- **Мышь** (обработчик int 33h @0x29352, push @0x29477): кольцо `0x450e4` из 32 записей по 0x14: +0 u16 маска события (1 движение, 2 ЛКМ↓, 4 ЛКМ↑, 8 ПКМ↓, 0x10 ПКМ↑, 0x20/0x40 средняя), +2 u16 состояние кнопок, +4 X, +8 Y (экранные, X драйвера делится на 4), +0xc/+0x10 микки (esi>>4, edi>>2). Указатели: запись `0x450dc`, чтение `0x450e0` (по модулю 0x280). Текущее положение `0x45098/0x4509c`, кнопки `0x450a8`, микки `0x450a0/0x450a4`, флаг «двигалась» `0x450ac`, последняя маска `0x45094`, флаги по битам `0x450b0..0x450c4`, `0x46264` — сохранённый ebx. Извлечение события `0x292ac` → `0x450c8` (маска+кнопки), `0x450cc/0x450d0` (X,Y), `0x450d4/0x450d8` (микки); `0x2929d` — ZF=1, если кольцо пусто.
- **Клавиатура** (int 9 @0x28c40): `0x44768[0x60]` удержание, `0x44708[0x60]` фронт, кольцо make-кодов `0x447d0[32]`, запись `0x447c8`, чтение `0x447cc`. `0x28cce` пусто?, `0x28cdd` взять скан-код, `0x28d11` скан-код в AL + ASCII в AH по таблицам (без модификаторов `0x448b4`, Shift `0x44852`, Alt+Ctrl `0x44916`, иначе `0x447f0`), `0x28c9d` очистить. Модификаторы: LShift `0x44792`, RShift `0x4479e`, Ctrl `0x44785`, Alt `0x447a0`; стрелки прокрутки читаются прямо из массива удержания: ↑ `0x447b0`, ↓ `0x447b8`, ← `0x447b3`, → `0x447b5`.
- Адаптер `Input` воспроизводит ровно эти записи: `mouseMove/mouseDown/mouseUp/keyDown/keyUp`, `attach(canvas, scale)` вешает браузерные события, `Input.scancode(KeyboardEvent.code)` — таблица скан-кодов набора 1.

## Кейсы
`cases/inp_*_m0_s0` (43) и `cases/inp_*_m2_s120` (50): курсор над полем/юнитом/зверем/краем/панелью/зданием, выбор кликом, рамкой (два вызова: старт + отпускание), ПКМ-снятие, режимы «идти/атака» с приказом, кнопки панели (команды, инвентарь ЛКМ/ПКМ, мелкие ЛКМ/ПКМ), правый drag, клик и отпускание на мини-карте, клавиши A/Z/G/N/Space/+/Ctrl+1/1/Alt+1/Ctrl+F5/F5/Tab/`, прокрутка стрелками и кнопкой у края, здание: выбор, заказ ЛКМ/ПКМ, курсор над кнопкой, конструктор: выбор, кнопка стройки, команда 0.
Игнорируемые при сверке области (пишут функции рисования, которые портирует render-core): кадр 0x1235f4..0x16e5f4, буферы фона под курсором 0x462fc..0x466fc и 0x46afc..0x46efc, банк VESA 0x47618, scratch блиттера 0x488d4, состояние отрисовки сцены 0x3eb10..0x41900, текстовый курсор после вывода 0x47004..0x4704c.

## Просмотрщик
`web/viewer.js` переведён на адаптер: события canvas → `Input`, каждые 40 мс вызываются 0x1133c, 0x12acd, 0x10d44, 0x12be6 (как в главном цикле), камера берётся из 0x31ae8/0x31aec, выделение — из бита 0x80 в +0x07 (лидер 0x31adc жёлтым). Ctrl+Space — старт/стоп симуляции.

## Не покрыто / замечания
- Чат и чит-коды (нужен 0x2a465), модальные экраны, сетевые ветки (`0x31b69`), 0x13182 (вариант поиска трупов, вызывающих нет), 0x14942 (сетевое ожидание).
- Прокрутка через край экрана проверена только логически (эффекты 0x23eb1 не сверялись).
- В `notes/core-loop.md` §2 таблица без модификаторов — 0x448b4, а не 0x447f0 (0x447f0 используется лишь при Alt без Ctrl); «F5–F8» — скан-коды 0x3f–0x42; кнопка стройки — прямоугольник 22 (518..550×176..208), «Store» — 20.

## Браузерное управление (2026-09-07): pointer-события + экранные кнопки
Жалобы были на просмотрщик, а не на ограничения браузера — адаптер `js/input.js` был минимальный (только mouse-события на самой канве). Переделано:
- **`attach(canvas, {onButton})` на pointer-событиях** с `setPointerCapture`: рамка выделения больше не рвётся, если курсор/палец ушёл за пределы канвы (раньше `mouseup` вне канвы терялся и рамка не закрывалась).
- **Пересчёт координат по фактическому размеру элемента** (`rect.width → 640`), поэтому канву можно масштабировать как угодно. Размер считает `fit()` в `web/viewer.js` (не `object-fit`: он даёт поля внутри элемента и ломает попадание). Проверено: клик в 50%/25% даёт ровно (320,120) на 1440×900, iPad и Pixel 5.
- **Тач:** у пальца нет кнопок — активная кнопка выбирается в UI (ЛКМ/ПКМ), а **долгое нажатие (450 мс без движения) временно переключает на другую**; если палец сдвинулся >6 px, это перетаскивание (рамка), таймер снимается. `touch-action:none` на канве, иначе браузер забирает жест себе. Перед каждым нажатием шлём `mouseMove` — у тача нет hover, а игра читает позицию курсора из своего состояния.
- **Клавиатура:** слушаем на window, `preventDefault` для известных скан-кодов, но **не трогаем сочетания с Meta** (Cmd+R/Cmd+W остаются браузеру); на `blur` отпускаем все клавиши, иначе они «залипают» при потере фокуса. Канва получила `tabindex` и фокус по нажатию.
- **Экранные кнопки** (`web/index.html`): мышь ЛКМ/ПКМ, залипающие Shift/Ctrl/Alt (нужны для Ctrl+цифра и Shift+клик), команды A/Z/G/N/центр/инфо/`/+/пауза, группы 0–9, Esc/F1–F8, стрелки прокрутки, пуск-стоп-шаг симуляции, полный экран. Нажатие — с удержанием (стрелки прокручивают, пока держишь); короткий тап удерживается ≥120 мс, иначе игра не увидит фронт в своём тике (тик просмотрщика 40 мс).
- `window.__jw = {mem, eng, input, F, draw, step, fit}` — доступ из консоли и автотестов.

Проверено в Chromium (playwright, через опубликованный сайт): рамка с отпусканием ВНЕ канвы выделяет юнита (лидер 0 → 384), ПКМ снимает выделение, кнопка N выбирает следующего юнита, кнопка ` переключает флаги мини-карты (47 → 43), залипающий Ctrl держит скан-код 0x1d, тач-долгое-нажатие даёт кнопку 2 (ПКМ) в `[0x450a8]`. Ошибок в консоли нет.
