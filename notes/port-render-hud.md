# Порт рендера — HUD, шаг 1: мини-карта и курсор мыши (js/render/hud.js)

## Портировано (реестр F, claims/*)
- **0x24843 мини-карта.** Рисует в закадровый буфер `[0x3e6e8]`(=0x1235f4) по позиции `[0x30388]/[0x3038c]` (528,16) и размеру `[0x30390]×[0x30394]` (96×96). Условие входа: `[0x31ae0]` бит 0 или бит 3. Начальная клетка сетки = `(0x3e7f0[camy>>5] << 8) | 0x3e6f0[camx>>5]` (таблицы «прокрутки» мини-карты для больших карт; на m0/m2/m9 обе нулевые), эти смещения запоминаются в `0x31b2c/0x31b30`. Цвет клетки: BI бит 0 = 0 → 0xff (не разведано); иначе владелец `MO>>4`, если 0 — `BI>>2` (здание), если и он 0 — цвет тайла `0x3e8aa[BG&0x7ff]`; для владельца `0x3e8a0[owner]` (это и есть «точки юнитов» — отдельного обхода пула нет). Два режима: бит 2 `[0x31ae0]` = 0 → 1 пиксель на клетку, = 1 → 2×2 (на трассах всегда 2×2). Если биты 0 и 1 сброшены и клетка без юнита, пиксель не перерисовывается, а затемняется через LUT `0x44f80` (в трассах не встречалось). Рамка вьюпорта цветом 0x12: `[0x31af0]×[0x31af4]` клеток (×2 в режиме 2×2) от `(camx>>5 − [0x31b2c], camy>>5 − [0x31b30])`. Затем рамка вокруг мини-карты цветом 0xf7 (строки y−1 и y+h длиной w+2, столбцы x−1 и x+w).
- **Курсор** (32×32, форма `[0x46274]+8`, 0 прозрачный, заголовок 8 байт — hotspot; формы MOUSECUR.27 уже лежат в снимке: таблица `0x46290[id]` → 0xdd72c…; позицию `0x46278/0x4627c` и форму ставит `js/port/input.js` (0x291ce)). Включён при `[0x4626c]!=0`. Координаты сравниваются беззнаково с 640/480, поэтому отрицательные (курсор у левого/верхнего края) просто не рисуются, как в оригинале.
  - `0x29720` — рисует форму в буфер; `0x29771` (esi=куда) — сохраняет 1024 байта фона из буфера; `0x297b5` (esi=откуда) — восстанавливает.
  - `0x299b4` **flip**: `[0x45090]++`, фон под курсором → `0x466fc`, курсор в буфер, `[0x4626a]=1`, `0x2ade6` (буфер 0x4b000 байт → VRAM = `eng.vram`, если задан), фон обратно из `0x466fc`, копия `0x466fc→0x462fc` (1024 байта — это НЕ палитра, как было сказано в port-render-core.md, а фон под курсором для программного перерисовывания при движении мыши `0x2995f/0x297f9/0x298a0`), `[0x4626a]=0`. Итог: в буфере курсора нет, в VRAM — есть; эталон `render_oracle.py` снимает VRAM, поэтому курсор в кадрах эталона присутствует.
  - `0x2ade6` — копия буфера в `eng.vram` (без банков).
- Подключение: `js/modules.js` импортирует `render/hud.js`; в `js/render/renderer.js` (файл render-core, изменено 2 строки) `this.hud = HUD` (список HUD-функций после сцены, сейчас `[0x24843]`) и `flip()` → `eng.vram = fb.px; call 0x299b4`. Браузерный `modules.browser.js` рендер не включает (gen_modules.py берёт только js/port), ничего не менял.

## Проверка
- `RECT=527,15,625,113 node js/test/rendertest.mjs traces/render_m0_t0 traces/m0_t0` (мини-карта с рамкой): 0 расхождений на 11 кадрах; render_m2_t0 (13 кадров) и render_m9_t3 (17 кадров) — 0 расхождений.
- `RECT=0,0,512,480 node js/test/rendertest.mjs traces/render_m0_t0 traces/m0_t0` **без EXCL курсора**: 0 расхождений на 11 кадрах (раньше требовался `EXCL=80,240,97,263`). m2_t0 с `EXCL=260,0,350,13` (счётчик еды) — 13/13; m9_t3 — расходятся только кадры с текстом (50, 75, 100, 125, 400: надписи над юнитами и сообщение в y 381..395), курсор везде совпадает.
- Весь кадр m0_t0 с исключением панели без мини-карты (`EXCL="512,0,640,15;512,113,640,480;512,15,527,113;625,15,640,113"`): 11/11 кадров без расхождений. Хеши пула юнитов совпадают (предупреждений «ВНИМАНИЕ» нет).
- Не покрыто трассами: режим 1 пиксель/клетка (бит 2 = 0), ветка затемнения (биты 0 и 1 сброшены), ненулевые таблицы 0x3e6f0/0x3e7f0 (карты крупнее 48×48), курсор, частично выходящий за экран. Перенесено буквально по декомпиляту/дизассемблеру.
