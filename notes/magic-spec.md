# Магия, заклинания, предметы и экипировка — полная спецификация с числами

Цель документа: реализовать магию и предметы JW на любом языке, не заглядывая в дизассемблер.

Всё ниже сверено с образом `pwar.img` (база 0x10000, `file_offset = addr − 0x10000`) и с портом
`reimpl/js/port/magic.js` + `combat.js` + `economy.js`, который сходится с эталоном (unicorn)
байт в байт. Числа проверены по трассам эталона — см. §13.
Смещения полей юнита — от базы записи (GAME-LOGIC §4.1); запись юнита 96 байт.

Машинные копии всех таблиц: `reimpl/data/magic_items.json`, `magic_spells.json`,
`magic_shot_tables.json`, `magic_effect_tables.json`.

## 1. Что такое MAG и мана

| поле | смещение | смысл |
|---|---|---|
| `MAG` | +0x0d | «магическая сила»: одновременно **максимум маны** и **порог открытия заклинаний** |
| `MANA` | +0x11 | текущая мана |
| `SKILLS` | +0x17 (u32) | битовая маска доступных приказов и заклинаний |

- Максимум маны = `MAG`. Отдельного поля «max mana» нет.
- `MAG` растёт при левел-апе (см. combat), и **каждый раз, когда он вырос, вызывается `0x1f475`**,
  который открывает новые заклинания (§4).
- Заклинание можно скастовать, если `SKILLS & (1<<бит)` **и** `MANA ≥ стоимость` (`0x14873`).

### 1.1 Регенерация маны и HP (`0x18ab2`)

Функция `0x18ab2(al)` вызывается из тика юнита с `al = 1`, **когда счётчик `0x31b66` равен 0**.
Счётчик увеличивается на 1 каждый игровой шаг и маскируется `& 0xf` — то есть **раз в 16 шагов**
(≈ раз в 0.88 с при делителе скорости 1).

> **Важно:** `0x31b66` — не `шаг & 0xf`. Это собственный счётчик, его стартовое значение
> берётся из карты/снапшота и в разных миссиях разное (в трассах: 0, 4, 7, 8, 12).
> Фаза регенерации от миссии к миссии сдвинута.

```
regen(al):                                    # 0x18ab2
  if STATE == 0x6f: return                    # свежий труп не регенерирует
  if HP < HPMAX:
      heal = true
      if TYPE < 14 and (HP & 3) == 0:         # люди и ручные динозавры «едят» за лечение
          heal = (eat(1) == успешно)          # 0x1c6e9: списать 1 еду из FOOD
      if heal:
          HP = min(HP + al, HPMAX)            # с насыщением по 0xff
  if MANA < MAG:
      MANA = MANA + al                        # с насыщением по 0xff
      if MANA > MAG: HP = MAG                 # !!! БАГ ОРИГИНАЛА: пишет в HP, а не в MANA
```

- **Еда за лечение**: юнит типа < 14 лечится только каждое 4-е очко HP (когда `HP & 3 == 0`)
  и только если у него есть еда: `FOOD ≥ 1` и в слотах 6..8 лежит `0x1e`. При `FOOD == 0`
  слот еды очищается и лечения нет. При `HP & 3 != 0` лечение бесплатное.
- **Баг с потолком маны** (`0x18b2e`): при переполнении маны обрезается **HP**, а не мана.
  При `al = 1` ветка недостижима (`MANA < MAG` ⟹ `MANA+1 ≤ MAG`), но воспроизводить надо.

### 1.2 Ускорение маны от тотема (`0x163e4`)

В начале тика юнита, **до** диспетчера состояний:

```
if (шаг & 3) == 0 and 5 <= TYPE <= 8:
    totem = [0x11, 0x1d, 0x13, 0x14][TYPE − 5]
    if totem in INV[9], INV[10], INV[11]:
        if MANA < MAG: MANA += 1
```

Здесь используется **основной счётчик шагов `0x31ab4`** (а не `0x31b66`).

| тип | класс | тотем (id) | название предмета |
|---|---|---|---|
| 5 | Elf | 0x11 (17) | Mystical Liquor |
| 6 | Wizard | 0x1d (29) | Skull Stick |
| 7 | Warlock | 0x13 (19) | Rock crystal |
| 8 | Ranger | 0x14 (20) | Dragon's Eye |

Итог по скорости восстановления маны:

| условие | +1 маны каждые | за 16 шагов |
|---|---|---|
| любой юнит | 16 шагов | 1 |
| маг 5–8 со своим тотемом в слотах 9–11 | 4 шага (+ базовая) | 5 |

То есть тотем даёт **×5 к регенерации маны**. Тотем должен лежать именно в «редких» слотах 9–11
(куда предметы 17/19/20/29 и попадают автоматически, см. §3.2) и именно «свой» — чужой не считается.

### 1.3 Кто вообще получает шаг

Регенерация и вся магия работают только у юнитов, которых обходит цикл юнитов:

```
if (FLAGS5B & 1): пропустить (юнит удалён)
f43 = +0x43
if f43 != 0:
    if (f43 & 3): f43 -= 1
    if (f43 & 0xfc) != 0:
        if (шаг & 3) == 0: f43 -= 4
        if STATE != 0x6f: пропустить юнит целиком   # парализован/оглушён
```

**Парализованный юнит не делает вообще ничего** — не ходит, не бьёт, не восстанавливает ману.

| бит | значение |
|---|---|
| 0x01 | «обычный» предмет (без него предмет считается редким при поиске на земле) |
| 0x02 | оружие → слоты 0–2 |
| 0x04 | щит → слоты 3–5 |
| 0x08 | товар арсенала: продаётся и покупается (только id 1–14) |
| 0x10 | редкая вещь/артефакт (id 15–29) |

### 2.1 Группы слотов инвентаря

Инвентарь — 12 байт от +0x1b, значение = id предмета (0 = пусто, 0x1e = еда).

| слоты | группа | как определяется |
|---|---|---|
| 0–2 | оружие | `флаги & 2` |
| 3–5 | щиты | `флаги & 4` |
| 6–8 | еда и зелья | не 2, не 4 (и id 0x1e — еда) |
| 9–11 | редкие вещи | `флаги & 0x10` и не 2/не 4 |

Правило подбора с земли (`0x1c470`): `base = (fl&2)?0 : (fl&4)?3 : (fl&0x10)?9 : 6`,
дальше первый пустой слот в `base..base+2`; если все три заняты — подбор не удаётся.
Еда (`0x1e`) кладётся в слот 6..8, где уже лежит еда, иначе в первый пустой из 6..8,
а количество прибавляется к `FOOD` (u16 +0x13) с потолком 0xffff.

Обратное правило (что юнит **готов** подобрать) считает `0x171d3` → `ax`:

```
ax = 0x1000                                      # бит «могу взять еду»
if 0x1e in INV[6..8]:   if FOOD == 0xffff: ax = 0
elif ни один из INV[6..8] не пуст:               ax = 0
al = число пустых слотов из 12
ah |= 1 за каждый пустой слот 0..2, 2 за 3..5, 4 за 6..8, 8 за 9..11
```
`0x170f6` (ИИ ищет предмет на земле кольцами вокруг себя, `RING_COUNT[(SPD>>4)+1]` клеток)
классифицирует найденный предмет так: еда → нужен бит 0x10; **`!(флаги & 1)` → группа 9–11**;
`флаги & 2` → 0–2; `флаги & 4` → 3–5; иначе → 6–8. Для всех реальных предметов обе
классификации совпадают.

> Проверка данных: в файлах карт встречаются юниты, у которых предмет лежит **не в своей группе**
> (редактор клал что угодно куда угодно). Движок это не чинит — правило действует только
> при подборе/покупке.

## 3. Экипировка

Экипированы могут быть один предмет из слотов 0–2 (`WEAPON`, +0x15) и один из 3–5
(`SHIELD`, +0x16). Значение = **номер слота**, 0xff = ничего.
Поля +0x09 / +0x0a хранят **id желаемого оружия/щита** (при загрузке карты туда пишется
то, что надето); ими пользуются автовыбор и арсенал.

### 3.1 Ручные действия игрока (приказ 0xe1, обработчик `0x19bbe`)

Приказ `0xe1` (клик по слоту инвентаря) исполняется **немедленно**, минуя состояние:
`edi = +0x47` — номер слота, `+0x4b` — флаг «снять».

| слот | `+0x4b = 0` | `+0x4b = 1` |
|---|---|---|
| 0–2 | надеть оружие: `WEAPON = слот`; если id ∈ 5..7 → `SHIELD = 0xff` | снять оружие (`WEAPON = 0xff`) |
| 3–5 | надеть щит: `SHIELD = слот`; если надетое оружие id ∈ 5..7 → `WEAPON = 0xff` | снять щит |
| 6–8 | **использовать предмет**: `0x1c5d6` (бонусы к статам), звук, слот очищается | – |
| 9–11 | ничего осмысленного (таблица переходов даёт «снять оружие») | – |

> **Ключевой момент, который легко потерять:** бонусы `+ATK/+DEF/…` из таблицы предметов
> применяются **только при «использовании» предмета** (`0x1c5d6`, вызывается ровно из двух
> мест: `0x19c76` — клик по слоту 6–8, и `0x1c77b` — автозелье). Надетое оружие/щит на статы
> **не влияет вообще** — оно работает только через таблицы урона боя (см. combat).
> Артефакты в слотах 9–11 «использовать» нельзя, их бонусы не применяются никогда;
> они полезны лишь как тотемы регенерации маны (§1.2) и как предмет для передачи/продажи.

`0x1c5d6(id)` — применение бонусов с насыщением:
```
HP   = min(HP + it.hp,   HPMAX)      # через 0xff, потом обрезание по HPMAX
MAG  = min(MAG + it.mag, 255)
MANA = min(MANA + it.mana, MAG)
ATK  = min(ATK + it.atk, 255);  DEF = min(DEF + it.dfn, 255);  SPD = min(SPD + it.spd, 255)
```

### 3.2 Автовыбор оружия (`0x1c791`) и щита (`0x1c8ec`)

Вызываются после подбора предмета с земли и после получения предмета от другого юнита,
и **только для типов < 4** (пещерные люди/воины/охотники) — маги и звери сами не переодеваются.

```
autoWeapon(u):                                     # 0x1c791
  if WEAPON != 0xff:
      if OWNER == локальный игрок: return          # у игрока движок оружие не меняет
      slot = первый из 0..2, у которого флаги предмета == 0x13   # артефакт-оружие
      if нет:
          want = +0x09;  if want == 0: return
          if INV[WEAPON] == want: return
          slot = первый из 0..2 с INV[slot] == want;  if нет: return
  else:
      want = +0x09
      slot = первый из 0..2 с INV[slot] == want   (если want != 0)
      if нет: slot = первый непустой из 0..2
      if нет: return
  WEAPON = slot
  if INV[slot] in 5..7: SHIELD = 0xff              # двуручное — щит слетает

autoShield(u):                                     # 0x1c8ec — то же для слотов 3..5,
  ...                                              # «артефакт-щит» — флаги == 0x15,
  if WEAPON != 0xff and INV[WEAPON] in 5..7: return   # с двуручным щит не надевается
  SHIELD = slot
```

- «Двуручное оружие» = **id 5, 6, 7** (Poison-Arrow, Fire-Arrow, Arrow). Именно они, а не все
  метательные: Boomerang (id 4) щиту не мешает.
- Приоритет автовыбора: **артефакт своей категории** (флаги ровно 0x13 для оружия и 0x15 для
  щита, т.е. id 15/16/18/22/23 и 21/24) → «желаемый» id из +0x09/+0x0a → первый непустой.
- **Квирк оригинала в `0x1c8ec`:** сравнение «уже надето то, что хотели» читает
  `INV[3 + SHIELD]` вместо `INV[SHIELD]` (адрес `0xe441e + слот`), т.е. промахивается на 3 слота.

### 3.3 Автозелье (`0x1c72b`)

Вызывается из анимации удара (`0x1a7cb`) сразу после нанесённого удара — у людей на 8-м кадре,
у зверей на 6-м (и только для типа < 0xe):

```
if HP >= HPMAX >> 1: return
for slot in 6..8:
    id = INV[slot]
    if id == 0 or id < 11 or id > 14: continue
    звук предмета;  INV[slot] = 0;  применить бонусы 0x1c5d6(id)
    return
```
То есть при HP ниже половины юнит выпивает **первое** зелье id 11–14 из слотов 6–8
(порядок слотов, не сила зелья).

### 3.4 Арсенал: купить/продать (`0x1763c` / `0x175e8`)

```
buy(id, slot):                        # 0x1763c
  if !(флаги & 8): отказ
  if цена > FOOD: отказ
  INV[slot] = id
  eat(FOOD)                           # !!! списывается ВСЯ еда юнита, а не цена

sell(slot):                           # 0x175e8
  if WEAPON == slot: WEAPON = 0xff
  elif SHIELD == slot: SHIELD = 0xff
  if флаги & 8:  FOOD += цена;  INV[slot] = 0      # возвращается ПОЛНАЯ цена
  # без флага 8 предмет только снимается, из слота не исчезает
```

**Баг оригинала:** покупка списывает всю переносимую еду независимо от цены; продажа
возвращает полную цену. Значит цепочка «купить дешёвое — продать» — бесконечный источник еды,
а покупка дорогого предмета всегда «съедает» весь запас.

Автоматическая закупка у арсенала (`0x173a3` + список `0x174af`): сначала распродать всё, что
можно (`0x1742f`/`0x175e8`), потом по очереди — оружие `+0x09` в первый пустой слот 0–2,
щит `+0x0a` в первый пустой 3–5, затем зелья: слот 6 ← id 14, слот 7 ← id 13, слот 8 ← id 13
(проверяется при этом цена id 12 — мелкий баг).

Продажа предмета **переносом** в арсенал (состояние 0x50, `0x19229`) считает деньги совсем
по другой формуле: `(5 * 0x315ec[id]) >> 1`, и только для id < 15
(id 1 → 165 еды вместо цены 2000). Подробности — тема экономики.

## 4. Умения и открытие заклинаний

`SKILLS` (+0x17, u32):
- биты 0–5 — базовые приказы (идти, атаковать, отдых, охрана, взять, отдать) — есть у всех;
- биты 8–26 — заклинания. **Бит `b` соответствует заклинанию `0x80 + (b − 8)`.**
  Биты 13, 18, 23 не используются (заклинаний 0x85, 0x8a, 0x8f нет).

### 4.1 Маски по типу юнита (`0x30e64` → `0x32760`)

`0x30e64[слот игрока]` — указатель на таблицу игрока: 9 значений u32 по типу юнита 0..8
(шаг таблицы 0x24 байта; слоты игроков 0..8). Значения по умолчанию **одинаковы у всех игроков**:

| тип | класс | маска | заклинания |
|---|---|---|---|
| 0 | – | 0x00000000 | – |
| 1–4 | Commoner/Warrior/Hunter/Constructor | 0x0000003f | – |
| 5 | **Elf** | 0x00001f3f | 0x80 0x81 0x82 0x83 0x84 |
| 6 | **Wizard** | 0x0003c03f | 0x86 0x87 0x88 0x89 |
| 7 | **Warlock** | 0x0078003f | 0x8b 0x8c 0x8d 0x8e |
| 8 | **Ranger** | 0x0700003f | 0x90 0x91 0x92 |

Итого 16 заклинаний: 5 / 4 / 4 / 3.

### 4.2 Открытие (`0x1f475`)

Вызывается при каждом изменении статов (левел-ап, смена класса, конверсия, читы):

```
if TYPE >= 9: return
mask = маска игрока[SLOT] для TYPE
for бит b в [8..12, 14..17, 19..22, 24..26]:
    if !(mask & (1<<b)):            continue
    if порог_MAG[b − 8] > MAG:      continue
    if SKILLS & (1<<b):             continue
    SKILLS |= 1<<b                  # + перерисовка панели, если юнит выбран
```

Пороги — из таблицы заклинаний (§5). Сводно:

| класс | заклинание | порог MAG |
|---|---|---|
| Elf | 0x80 / 0x81 / 0x82 / 0x83 / 0x84 | 30 / 50 / 70 / 90 / 110 |
| Wizard | 0x86 / 0x87 / 0x88 / 0x89 | 30 / 45 / 65 / 90 |
| Warlock | 0x8b / 0x8c / 0x8d / 0x8e | 30 / 50 / 90 / 100 |
| Ranger | 0x90 / 0x91 / 0x92 | 30 / 50 / 70 |

### 4.3 Маска — не инвариант

Разрешение на каст проверяет **только `SKILLS`** (`0x14873`), маска нужна лишь для открытия.
В файлах карт встречаются юниты с битами вне маски своего класса — например в миссии 9
есть Ranger с открытым битом 12 (заклинание Elf'а 0x84). Такой юнит действительно может
кастовать чужое заклинание. Реимплементация не должна «чинить» SKILLS по маске.

### 4.4 Проверка «можно ли кастовать» (`0x14873`)

```
can(bit):
  if !(SKILLS & (1<<bit)): нет
  return MANA >= стоимость_маны[bit − 8]
```

## 5. Таблица заклинаний (`0x30b5e`)

Запись 4 байта, индекс = `id − 0x80`: **`[сила u8, 0, порог MAG u8, стоимость маны u8]`**.

> Раньше эта таблица читалась как `0x30b60 [порог, мана, сила, 0]` — из-за этого «сила»
> оказывалась приписана соседнему заклинанию. Правильный старт — `0x30b5e`:
> сила заклинания `k` лежит по адресу `0x30b5e + k*4`, порог и цена — по `0x30b60 + k*4`
> и `0x30b61 + k*4` (именно так их читают `0x1f475`, `0x14873` и `0x1c092`).

Имена — из строк подсказки курсора (лежат подряд от `0x41f5c`; таблица указателей `0x41ed8`
для режимов 9–13 содержит смещённые значения, поэтому имена надёжнее брать по порядку строк).

### 5.1 Списание маны (`0x1c092`)

```
cost = стоимость[id & 0x7f]
MANA = (MANA < cost) ? 0 : MANA − cost
```
Списывается **в момент каста** (внутри `0x1b917`), а не при выдаче приказа. Если каст не удался
(нет свободного слота в пуле снарядов), мана не тратится и XP всё равно уже начислен (см. §6).

### 5.2 Дальность каста

Состояния подхода (§7) считают радиус так:

```
R = ((SPD >> 5) << 4) + 0x80          # для всех заклинаний по цели
R = ((SPD >> 5) << 4) + 0x60          # для 0x86 (Framing-Ball)
```

| SPD | 0–31 | 32–63 | 64–95 | 96–127 | 128–159 | 160–191 | 192–223 | 224–255 |
|---|---|---|---|---|---|---|---|---|
| R (обычный) | 128 | 144 | 160 | 176 | 192 | 208 | 224 | 240 |
| R (0x86) | 96 | 112 | 128 | 144 | 160 | 176 | 192 | 208 |

Проверка (`0x1a1e4`): каст возможен, только если **кастер стоит ровно на тайле**
(`X & 0x1f == 0 && Y & 0x1f == 0`) и прямоугольник цели пересекается с прямоугольником кастера,
расширенным на R. Габариты берутся **по типу кастера** (квирк: для цели используется размер
кастера), но у всех мобильных юнитов это 32×32, поэтому на практике условие сводится к

```
|Xцели − Xкастера| <= R + 32  и  |Yцели − Yкастера| <= R + 32
```

Для заклинания в точку (0x8b) используется `0x1a2f2` — квадрат `±R` вокруг кастера
плюс то же требование «стоять на тайле».

## 6. Что делает каждое заклинание (`0x1b917`)

Общий каркас каждой ветки: `XP += таблица`, звук `0x38f98[id − 0x80]`, создать «снаряд-эффект»,
применить мгновенную часть, списать ману. **XP начисляется до всех проверок** — даже если
эффект не создался (пул снарядов пуст), опыт уже получен.

Снаряд-эффект (`0x1bffc` — на цель, `0x1c052` — в точку) — запись пула снарядов 36 байт:
`+0 = id заклинания` (как отрицательный байт → диспетчер `0x1ac98`), `+1 = 0xff` (счётчик),
`+4 = кастер`, `+8 = цель`, `+0xc/+0xe = позиция` (центр цели по её типу: `0x30456/0x30458`),
`+0x10 = 0`.

| id | мгновенно | обработчик эффекта | тайминг и числа |
|---|---|---|---|
| 0x80 | `heal(цель, 20)` с обрезанием по HPMAX | `0x1b02c` | только картинка, 8 тиков |
| 0x81 | `heal(цель, 15)`, затем обход 21 клетки спирали `0x305d0` вокруг **цели**: каждому своему юниту на клетке — свой эффект и `heal(15)` | `0x1b040` | 8 тиков |
| 0x82 | – | `0x1b054` | каждый тик `HP += 1` (если HP < HPMAX), 171 тик; если цель стала трупом (0x60) — эффект гаснет |
| 0x83 | – | `0x1b08f` | каждый тик `HP = HPMAX`, 201 тик |
| 0x84 | воскрешение, см. §6.1 | `0x1b0ca` | 13 тиков картинки |
| 0x86 | огненный шар, см. §6.2 | `0x1b0de` (тип снаряда 0xa0+dir) | урон 10, самонаведение |
| 0x87 | – | `0x1b277` | на 9-м тике `damage(цель, 20)` |
| 0x88 | – | `0x1b2a9` | на 13-м тике `damage(цель, 30)` |
| 0x89 | `цель.+0x43 \|= 0xfc` | `0x1b2db` | маркер живёт, пока `+0x43 & 0xfc != 0` (≈252 шага) |
| 0x8b | эффект в точку `(DSTX, DSTY)` | `0x1b2ef` | 141 тик; каждый **чётный** тик по 3×3 тайлам вокруг точки: первому найденному юниту на тайле — 1 урона; юниты типа 7 (Warlock) невредимы |
| 0x8c | см. §6.3 | `0x1b3de` (пусто) | – |
| 0x8d | эффект «от себя», запоминает камеру | `0x1b3df` | 21 тик тряски камеры (смещения ±32/±64 из `0x36fe0`, случайный из 14), затем всем в прямоугольнике 640×480 вокруг кастера: `HP -= rand(15) + 30`; при HP ≤ 0 — обычная смерть с XP убийце |
| 0x8e | эффект «от себя» | `0x1b529` | на 11-м тике всем в квадрате ±0x120 (288×288 px) вокруг точки: `HP -= rand(70) + 50`; при HP ≤ 0 — `HP = 0, STATE = 0x6f` **без XP и без лута** |

| 0x92 | эффект, `+0x10/+0x12 = DSTX/DSTY` | `0x1b6a3` | на 5-м тике телепорт кастера в свободную клетку около точки, на 9-м эффект гаснет |

Общая деталь: счётчик `+1` у эффекта стартует с `0xff`, первый инкремент даёт 0 — поэтому
«через N тиков» = N+1 вызов обработчика.

### 6.1 Воскрешение / подчинение (0x84)

Приказ `0xa4`, курсор наводится **на труп** (`0x11e6a`: `STATE == 0x60`, тип < 0x0e).
Состояние 0x84 (`0x19872`) требует, чтобы цель была именно в состоянии **0x60** — проверка
инвертирована относительно всех остальных заклинаний (там цель в 0x60 означает «цель пропала»).

```
взять запись из свободного списка пула (0x1aaac); если пула нет — ничего не делать
скопировать 0x58 байт цели, начиная с +4                     # тип, статы, координаты
+5/+6 (SLOT, OWNER) = SLOT/OWNER кастера                     # новый юнит служит кастеру
+0x08 = 0
для HPMAX, ATK, DEF, SPD:  v = (v > 20) ? v − 20 : 20        # −20, пол 20
для MAG:                   v = (v > 20) ? v − 20 : 0         # у MAG пол 0
HP = HPMAX;  MANA = 0;  WEAPON = SHIELD = 0xff
STATE = 0x49;  ATKCTR = 0;  инвентарь и FOOD обнулены;  FLAGS5B = 0
SKILLS = 0x3f;  0x1f475 (открыть заклинания по MAG)
найти свободную клетку (0x1ccdd) около координат трупа, встать туда, отметиться в сетках
если владелец — локальный игрок: открыть туман
труп: FLAGS5B |= 1 (удалён), запись возвращается в свободный список
```

Итог: **труп любого игрока превращается в живой юнит того же типа под флагом кастера**,
со всеми статами минус 20 и без вещей. Ограничения по владельцу трупа нет.

### 6.2 Огненный шар (0x86, `0x1bc8a`)

```
взять запись пула;  снаряд.+3 = 10 (урон, константа 0x30b76)
DIR кастера = направление на цель (0x1a95d + уточнение 0x1aa10)
0x1b730(вид = 0xa0): тип снаряда = 0xa0 + DIR, время жизни = (0x3055e[SPD>>5] + 40) >> 1
снаряд.+1 += 0x10                       # ещё +16 тиков жизни
списать ману (18)
```
Тип 0xa0+dir обрабатывается `0x1b0de`: полёт как у стрелы (4 подшага за тик), но **каждые
4 тика направление пересчитывается на цель** — шар самонаводящийся. При попадании наносит
ровно `+3 = 10` урона, **без учёта DEF и щита цели**.

Время жизни по SPD (`0x3055e`, шаг 4 байта, индекс `SPD>>5`): 64/96/128/160/192/224/256/288 →
жизнь `(v+40)/2 + 16` = 68/84/100/116/132/148/164/180 тиков.

### 6.3 Fire-Dance (0x8c)

```
XP += 20;  звук 0x38f98[6]  (звук огненного шара, не свой — квирк)
edi = первый чужой живой юнит в квадрате ±0x120 вокруг кастера (0x1c0b2)
если такого нет — выйти (мана не тратится, XP уже начислен)
сохранить MANA в 0x36fde
пока есть цели: выпустить в каждую огненный шар (0x1bc8a — он списывает 18 маны за штуку)
восстановить MANA из 0x36fde
списать 32 маны
```
То есть за 32 маны Warlock выпускает по 10-уронному самонаводящемуся шару **в каждого**
врага в области 288×288 px.

### 6.4 Область поиска врагов (`0x1c0b2` / `0x1c0b8`)

```
dx = (X − 0x80) & 0xffe0;  bx = (Y − 0x80) & 0xffe0
квадрат [dx, dx+0x120) × [bx, bx+0x120)            # 288×288 px = 9×9 тайлов
условия: другой владелец, STATE != 0x60, !(FLAGS5B & 1)
```
Тот же квадрат использует эффект 0x8e, но там фильтр владельца сравнивает с константой **0x0e**
(владельца 14 не существует) → **под удар попадают и свои**.

## 7. Состояния и автомат каста

### 7.1 Приказ → состояние

Приказ лежит в `+0x46` (код), `+0x47` (цель, u32), `+0x4b/+0x4d` (точка).
Он применяется в тике юнита, **только когда юнит стоит ровно на тайле**:
`STATE = приказ; TARGET = +0x47; DSTX = +0x4b; DSTY = +0x4d; +0x46 = 0xff`,
после чего на **том же шаге** выполняется новое состояние.

Коды приказов заклинаний: `0xa0 + (id − 0x80)` для 0x80..0x8e и `0xb0 + (id − 0x90)`
для 0x90..0x92. Проверка доступности в UI/ИИ: `0x14873(приказ − 0x98)`.

### 7.2 Диспетчер состояний ≥ 0x80 (`0x182c8[STATE − 0x80]`)

| состояния | обработчик | что делает |
|---|---|---|
| 0xa0–0xa4, 0xa6–0xa9, 0xac | `0x19b0a` | `DSTX/DSTY = позиция цели & 0xffe0`, старт движения (`0x1db94`), `STATE −= 0x20` |
| 0xab, 0xad, 0xae | `0x19b41/49/51` | просто `STATE −= 0x20` (идти никуда не надо) |
| 0xb0, 0xb1, 0xb2 | `0x19b59` | `STATE −= 0x20`, `ATKCTR = 4`, **сразу каст** `0x1b917` |
| 0x80–0x83 | `0x197e5` | подход к цели с R = `((SPD>>5)<<4)+0x80`, в радиусе — каст |
| 0x84 | `0x19872` | то же, но цель обязана быть в состоянии 0x60, иначе приказ сбрасывается |
| 0x86 | `0x1990c` | подход с R = `+0x60`; если цель == сам — отмена |
| 0x87–0x89 | `0x1999e` | как 0x197e5 |
| 0x8b | `0x19a2b` | цель — точка `+0x4b/+0x4d`; проверка квадратом `0x1a2f2`, в радиусе — каст |
| 0x8c | `0x19a91` | найти любого врага рядом (`0x1c0b2`); нет — приказ 0x3f, есть — каст немедленно |
| 0x8d, 0x8e | `0x19abd/0x19adc` | каст немедленно, без проверок |
| 0x90–0x92 | `0x19afb` | каста нет (он уже был в 0xb0–0xb2): `ATKCTR = 0`, `STATE += 0x40` |
| 0xc0–0xc4, 0xc9, 0xcb–0xcd, 0xd0–0xd2 | `0x19b78` | `ATKCTR += 1`; при `>= 2` → приказ 0x3f (охрана) |
| 0xc6, 0xc7, 0xc8 | `0x19b8c` | `ATKCTR += 1`; при `>= 2` → **приказ 0x1f (атаковать ту же цель)** |
| 0xce | `0x19ba7` | `ATKCTR += 1`; при `>= 2` → **приказ 0x6f, т.е. кастер умирает** |

Подпрограмма подхода:
```
approach(u, target, add):
  R = ((SPD >> 5) << 4) + add
  if !inRange(u, target, R):                        # 0x1a1e4
      if шаг движения (0x1dc43) вернул «идём» — выйти
      # «прибыли», но цель не в радиусе: пересчитать точку и начать движение заново
      DSTX/DSTY = позиция цели & 0xffe0;  0x1db94
      выйти
  castNow(u, target)

castNow(u, target):
  0x1b917(STATE, u, target)      # эффект + мана + XP
  кадр стойки (0x1a773);  ATKCTR = 0;  STATE += 0x40

targetGone(u):  приказ = 0x3f;  сделать шаг движения
```
Цель считается пропавшей, если её `STATE == 0x60` (для 0x84 — наоборот).

**Полный цикл каста:** приказ `0xa0+n` → состояние `0xa0+n` → (путь) `0x80+n` → подход →
каст → `0xc0+n` → 2 шага анимации → приказ `0x3f` (или `0x1f` для 0x86–0x88, или `0x6f` для 0x8e).

### 7.3 Телепорт (0x92 / приказ 0xb2)

Приказ `0xb2` кладёт точку в `+0x4b/+0x4d` → `DSTX/DSTY`. Состояние 0xb2 кастует сразу
(радиус **не проверяется** — телепорт работает на любую дистанцию, лишь бы хватило 30 маны),
создавая эффект с `+0x10/+0x12 = DSTX/DSTY`. Обработчик `0x1b6a3`:

```
+1 += 1;  если >= 8 — эффект удалить
если +1 != 4 — ждать
снять отпечаток с сетки (0x1a42c)
найти свободную клетку около (DSTX, DSTY) — 0x1ccdd
X, Y = найденная клетка;  поставить отпечаток (0x1a3db)
если владелец — локальный игрок: открыть туман (0x1a4cc)
если +0x52 != 0xff: приказ 0x3f   иначе  STATE = 0x2f
```

ИИ пользуется телепортом вместо ходьбы: при открытом бите 0x1a и чебышёвском расстоянии
до цели ≥ 320 px состояние 0x0f выдаёт приказ 0xb2 (см. movement-spec §8), а «прогулка»
`0x16841` телепортирует в случайную клетку карты.

## 8. Обычная атака магов (`magicShot`, таблицы `0x37990`+)

Маги (типы 5–8) в ближнем бою **никогда не бьют в упор** — `0x1e758` для них всегда выпускает
магический снаряд. Блок таблиц — 0x47 байт: 40 байт бонуса по типу цели + 31 байт вычета по
id щита цели.

```
dmg = ((max(ATK − DEF, 0)) >> 4) + (ATK >> 5) + 1        # базовая формула 0x1ea75
dmg = dmg + A[тип цели]
если у цели щит: dmg = max(dmg − B[id щита], 1)          # (v < 0 → 1)
создать снаряд вида kind + DIR, урон = dmg
```

| тип | A | B | вид снаряда |
|---|---|---|---|
| 5 Elf | 0x37990 | 0x379b8 | 0x18 |
| 6 Wizard | 0x379d7 | 0x379ff | 0x20 |
| 7 Warlock | 0x37a1e | 0x37a46 | 0x28 |
| 8 Ranger | 0x37a65 | 0x37a8d | 0x30 |

**Бонус по типу цели `A` (индекс = тип цели 0..39):**

| тип цели | 0–4 | 5 | 6 | 7 | 8 | 9–10 | 11 | 12–18 | 19–23 | 24 | 25 | 26 | 27–39 |

## 9. Как ИИ решает кастовать

Решения принимает `0x163e4` перед диспетчером, по старшему нибблу состояния:
`1x` → `0x16531` (бой), `2x` → `0x16508` (отдых), `3x` → `0x16598` (охрана/задачи).

### 9.1 В бою (`0x16531`)

```
if ATKCTR != 0: выйти                             # думаем только между ударами
if слаб (0x166e0): попробовать вылечить себя (0x1674b); если выбрал — выйти
if TYPE < 5 or TYPE > 8: выйти                    # дальше — только маги
if рядом раненый союзник в бою (0x17014): вылечить его (0x16916); если выбрал — выйти
if TARGET != 0: выбрать атакующее заклинание (0x16a10)
```

`0x166e0` («слаб»): `HP >= HPMAX/2` → нет; `HP < 10` → да; `HP < HP цели / 2` → да;
иначе `HP+ATK+DEF` своё < целевое → да.

`0x17014`: обход колец `RING_COUNT[(SPD>>4)+1]` вокруг себя; союзник считается раненым,
если он в состоянии `0x1x` или `0x30..0x33` и `HP <= HPMAX/2`.

### 9.2 Выбор лечения (`0x1674b` — себя, `0x16916` — союзника)

Перебор по возрастанию силы; **цикл прерывается на первом недоступном заклинании**:

| бит | заклинание | оценка |
|---|---|---|
| 8 | 0x80 | `min(HPMAX − HP, 20)` |
| 9 | 0x81 | сумма `min(HPMAX − HP, 15)` своих в 9 клетках (практически всегда 0, см. §11) |
| 0xa | 0x82 | `min(HPMAX − HP, HP − 1)` |
| 0xb | 0x83 | `min(HPMAX − HP, HP)` |

Побеждает максимум, при равенстве — **последнее** (более сильное). Если все оценки 0 и это
самолечение — вместо заклинания ИИ идёт «гулять» (`0x16841`).

### 9.3 Выбор атакующего заклинания (`0x16a10`)

Предусловие: `TARGET != edi` и `MANA >= HP || MANA >= MAG/2`.

| порядок | бит | заклинание | оценка | приоритет при равенстве |
|---|---|---|---|---|
| 1 | 0x16 | 0x8e Self-destruction | 0, если `HP >= 15`; иначе Σ`min(HP,50)` врагов − своих в ±0x120 | – |
| 2 | 0x15 | 0x8d Earthquake | Σ`min(HP,30)` врагов − своих в 640×480 | – |
| 3 | 0x14 | 0x8c Fire-Dance | Σ`min(HP,10)` врагов − своих в ±0x120 | – |
| 4 | 0x13 | 0x8b Poison-Gas | (число врагов − своих) в ±32 px вокруг цели, тип 7 не считается | – |
| 5 | 0x11 | 0x89 Ice | 0, если цель уже парализована, иначе HP цели | строгое `>` |
| 6 | 0x10 | 0x88 Lighting | `min(HP цели, 30)` | – |
| 7 | 0xf | 0x87 Roaring-Sound | `min(HP цели, 20)` | – |
| 8 | 0xe | 0x86 Framing-Ball | `min(HP цели, 10)` | – |

Пункты 1–2 рассматриваются только у игроков под управлением ИИ (`0x32aec[владелец] != 0`).
Обновление «лучшего» нестрогое (`cur <= new`), кроме бита 0x11, поэтому **при равенстве очков
выигрывает последнее по списку, т.е. самое слабое заклинание** — ИИ склонен спамить
огненными шарами.

### 9.4 Отдых (`0x16508`)

Состояние `2x`: выйти из отдыха (приказ 0x3f), когда `HP == HPMAX` **и** `MANA == MAG`.

## 10. Артефакты: случайное появление

В начале каждого шага (`0x13f4c`) — **внутри ветки `0x31b69 != 0`** (флаг режима игры:
в 1 его ставит обработчик меню `0x2333c`, в 0 — `0x22bc5`; в трассах эталона он равен 0,
поэтому там артефакты не появляются вообще):

```
if (шаг & 0x1f) != 0:  ничего                        # раз в 32 шага
if 0x3c53f == 0:       ничего                        # опция-галочка меню (0x22f52)
r = rand(10000);  if r > 0x32: ничего                # 51 исход из 10000 = 0.51 %
id  = 0x0f + rand(15)                                # 15..29 — только артефакты
y   = rand(mapH) * 32
x   = rand(mapW) * 32
создать предмет (0x1cdf3); при успехе — сообщение «--- Appear the <имя> ---»
   (таблица строк 0x35444, индекс = id − 0x0f)
```

Порядок вызовов ГСЧ важен: сначала 10000, потом 15, потом mapH, потом mapW.
Ожидание: 0.51 % × (1/32 шага) ≈ один артефакт на 6270 шагов ≈ раз в 5.7 минуты
при делителе скорости 1.

## 11. Странности оригинала, которые надо повторить

1. **Бонусы предметов применяются только при «использовании»** (слоты 6–8). Надетое оружие
   и щит на статы не влияют, а артефакты в слотах 9–11 «использовать» вообще нельзя —
   их `+ATK/+MAG/…` не применяются никогда (§3.1).
2. **`0x18b2e`: при переполнении маны обрезается HP, а не мана** (при `al=1` ветка мертва).
3. **Покупка в арсенале списывает всю еду юнита**, а не цену; продажа возвращает полную цену
   (§3.4). Продажа переносом в арсенал считает деньги по совсем другой таблице.
4. **`0x1c8ec` читает `INV[3 + SHIELD]`** вместо `INV[SHIELD]` при проверке «уже надето нужное».
5. **Заклинание 0x8e бьёт по своим**: фильтр владельца сравнивает с константой 0x0e,
   которой ни у кого нет. Землетрясение 0x8d владельца вообще не проверяет.
   А кастер 0x8e после анимации получает приказ 0x6f и умирает (`0x19ba7`).
6. **0x8e убивает мимо `0x1ebdc`**: жертве просто ставят `HP = 0, STATE = 0x6f`, поэтому
   ни XP убийце, ни выпадения вещей из инвентаря нет.
7. **0x8c звучит чужим звуком** (индекс 6 = звук 0x86) и **сохраняет/восстанавливает ману**
   вокруг серии внутренних выстрелов, чтобы списать ровно 32 один раз.
8. **Порядок приказа для 0xac лишний**: `0x19b0a` строит путь к цели, хотя состояние 0x8c
   кастует немедленно; при клике мышью цель = 0, и путь строится к записи пула №0.
9. **Ядовитое облако 0x8b проверяет границы карты «наперекрёст»**: Y сравнивается с `mapW`,
   X — с `mapH`.
10. **Массовое лечение 0x81 проверяет границы карты по младшему байту** (`(tile & 0xff) < mapW`),
    поэтому на картах шире 256 тайлов оно вело бы себя странно; обходятся клетки спирали 1..21
    (клетка 0 — сама цель, она лечится напрямую до цикла).
11. **Оценщик массового лечения `0x16f5e` (для 0x81) сравнивает границы инвертированно**
    (`jae` вместо `jb`) и читает сетку MO по строке 0 — практически всегда даёт 0.
12. **`0x170f6` при непищевом предмете затирает счётчик колец флагами предмета** —
    поиск предметов на земле прерывается непредсказуемо.
13. **Маска класса не ограничивает каст**: проверяется только `SKILLS`, а он может прийти
    из файла карты с «чужими» битами (§4.3).
14. **Пул спеллов знает 0x93 и 0x94** (пороги 90/110, мана 40/70), но битов и обработчиков
    у них нет.
15. **XP за каст начисляется до проверок** — если пул снарядов пуст, опыт получен, а мана нет.
16. **Огненный шар (0x86) игнорирует DEF и щиты** — всегда ровно 10 урона.
17. Таблица подсказок курсора `0x41ed8` для режимов 9–13 указывает мимо начала строк
    (на 2 и 4 байта позже); сами строки лежат подряд от `0x41f5c` в порядке режимов.

## 13. Как это проверено

`tools/spec_check_magic.py` — **независимая** реализация формул этого документа на Python
(порт `js/port/*.js` не импортируется, числовые таблицы читаются прямо из `pwar.img`).
Скрипт берёт состояние пула юнитов на записи `k` трассы эталона, применяет формулу шага
и сравнивает с записью `k+1`.

Запуск: `python3 tools/spec_check_magic.py` (все трассы) или с явным списком каталогов.

Результат по всем 11 трассам (`m0_t0`, `m0_t0_orders`, `m1_t1`, `m2_t0`, `m3_t5`, `m5_t0`,
`m9_t3`, `long_m1_t1`, `long_m2_t0`, `long_m5_t0`, `long_m9_t3`; 10 700 шагов):

| проверка | совпало | не совпало |
|---|---|---|
| мана после шага (регенерация + списание при касте) | 1 143 678 | 0 |
| HP/еда при регенерации (шаг регенерации, вне боя) | 1 884 | 0 |
| XP за каст | 80 | 0 |
| каст только когда цель в радиусе `((SPD>>5)<<4)+0x80` / `+0x60` | 64 | 0 |
| новые биты умений = пройденный порог MAG | 6 | 0 |
| открытое заклинание ⟹ `MAG ≥ порога` | 463 399 | 0 |
| `MANA ≤ MAG` | 1 347 838 | 0 |
| двуручное оружие 5–7 ⟹ щита нет | 26 378 | 0 |
| подобранный предмет попадает в свою группу слотов | 24 | 0 |
| слот оружия ∈ {0,1,2,0xff}, слот щита ∈ {3,4,5,0xff} | 1 347 838 ×2 | 0 |

**Вердикт скрипта: расхождений 0.**

Что при этом реально «прожито» в трассах:

- **85 кастов**, из них по заклинаниям: 0x80 — 45, 0x83 — 10, 0x8d — 10, 0x8c — 8,
  0x86 — 4, 0x87 — 4, 0x8b — 2, 0x82 — 1, 0x8e — 1. По трассам: long_m5_t0 — 27, m5_t0 — 26,
  long_m9_t3 — 18, m3_t5 — 12, m9_t3 — 2.
- **252 шага** в состояниях анимации каста (0xc0–0xd2) — автомат §7.2 отработан.
- **6 открытий заклинаний** по достижению порога MAG.
- 2 случая «каст + убийство на том же шаге» и 3 «каст + удар на том же шаге» вынесены
  в отдельные счётчики: там XP складывается из нескольких источников
  (`0x1e758` даёт +1 XP обеим сторонам удара, убийство — `(ΣСтатов)²/4`).

### Чего трассы НЕ подтверждают (честный список)

- **Регенерация маны от тотема (§1.2) не встретилась ни разу.** Тотем есть у 13 магов
  (14 300 шагов «с тотемом»), но у всех них мана всё время равна MAG, поэтому ветка
  `MANA < MAG` не срабатывала. Правило взято из порта (сверен с unicorn) и дизассемблера,
  но положительных примеров в трассах нет. Все 1 018 наблюдённых приростов маны объяснены
  базовым правилом «раз в 16 шагов».
- Не встретились касты 0x81, 0x84, 0x88, 0x89, 0x90, 0x91, 0x92 — их эффекты описаны
  по порту и дизассемблеру, но не подтверждены трассой.
- Эффекты-снаряды (§6) в трассах не сохраняются (`steps.bin` содержит только пул юнитов
  и еду игроков), поэтому тайминги «через N тиков» и суммы урона взяты из порта, а не
  измерены. Косвенно они подтверждаются тем, что порт целиком сходится с эталоном.
- Спавн артефактов (§10) не проверялся: предметы на земле в трассу не пишутся.
  Числа (32 шага, 51/10000, id 15 + rand(15)) прочитаны прямо из кода `0x13f85..0x13ff0`.
  Более того, в трассах внешний флаг `0x31b69` равен 0, поэтому этот блок там ни разу
  не выполняется.
- Покупка/продажа в арсенале и «использование» предмета в трассах не встретились
  (нет ни одного изменения слота с применением бонусов), формулы §3.1/§3.4 — из кода.
- Проверка «предмет лежит в своей группе слотов» как инвариант **неверна** для юнитов из
  файлов карт (2 таких юнита в трассах) и для записей зданий (тип ≥ 26 использует
  байты +0x09..+0x26 под другое); проверяются только предметы, подобранные во время трассы.
